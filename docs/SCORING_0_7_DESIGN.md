## 1. 问题：0.6 把饱和点从地板搬到了天花板

0.5.0-anchored 的病是扣分账本溢出，分数在地板饱和。0.6.0-band-anchored 修好了地板，但同一个病在天花板复发。

### 1.1 实测：A 带窗口有 73% 不可达

`position` 的两项 —— `craft_ratio` 与 `1 − defect_density` —— 在 A 带内都被结构性地钉在高位：

- **`defect_density` 的分母包含 veto/core 判据**，而 A 带的准入前提正是这些判据全部无问题。它们只进分母、永不进分子，把密度稀释到接近 0。
- **`craft_ratio` 被 core 红线抬出一个地板**：多个 craft set 成员同时是 core 判据，A 带下恒为 YES。

穷举全部可达组合的结果：

| 带位 | 窗口 | 实际可达 | 跨度 | 窗口利用率 |
|---|---|---|---|---|
| A | `[85,94]` | 91.58 – 94.00 | 2.42 | **27%** |
| B | `[75,84]` | 77.37 – 83.69 | 6.32 | 70% |
| 记录型 | `[68,74]` | 68.92 – 71.79 | 2.87 | **48%** |
| C | `[45,59]` | 45.00 – 58.29 | 13.29 | 95% |

A 带 9 分里 6.58 分构造上不可达；可达的不同整数分只有 **3 个**。B 带的病轻一些但同样存在——它允许分子变动，所以利用率有 70%，而不是初稿所说的没有这个病。

### 1.2 craft set 与 core 红线的重叠

| 席 | craft set | 其中属 core/veto（A 带下恒 YES） | A 带内 `craft_ratio` 可取值 |
|---|---|---|---|
| 04 结构 | N3, TW2, TW4, SC1 | N3, TW4 | 0.75 / 1.0 |
| 05 人物 | P2, P3, P4, P7 | **P2, P3, P4** | 0.75 / 1.0 |
| 06 语言 | L5, L7, TW3 | 无 | 0.667 / 1.0 |
| 07 情感 | E3, E6, E7, TW14 | E3 | 0.75 / 1.0 |

每席在 A 带内只有两档。**席 05 的 craft 门是死码**：`craft_ratio` 恒 ≥ 0.75 ≥ 0.6，永不否决 A 带晋升，「四席门」实为三席门。

### 1.3 已验证的反直觉结论

以下三条都经穷举验证，用于排除错误的修法：

1. **重划窗口不解决死区。** 利用率完全由 `placement` 的可达区间决定，与窗口边界无关。验证：在不动 `position` 公式的前提下把 A 窗口换成任意宽度，利用率恒为 27%——例如换成 `[80,90]` 后可达区间是 87.31–90.00，换成 §3 最终采用的 `[80,89]` 后是 86.58–89.00，比例不变。
2. **增加判据条数不解决死区。** craft 集与非 craft extended 集瓜分同一个有限判据池，此消彼长。实测：只修分母 64% → 解耦为 extended-only 61% → 每席补至 3 条 58% → 补至 4 条 54%。「理想配置」（每席 4 条 craft 无强制 + 5 条非 craft extended）仅 62%。
3. **craft 门本身构成 A 带分数的地板。** 门是 0.6 ⇒ `p_i ≥ 0.3` ⇒ `placement ≥ 0.3`。A 带内 `placement` 的解析可达区间是 `[0.3552, 1.0]`，不是 `[0,1]`。

### 1.4 S 不可达的根因

`SKILL.md` 已披露：判据向量无法区分 S 与 A（18 篇锚文校准中两者四席 `craft_ratio` 均落在 0.87–1.00）。**S 不可达不是窗口没开，而是没有能把 S 从 A 分出来的信号。** 任何只调窗口或阈值的方案都无法让 S 可达。

### 1.5 阈值落在观测空洞

锚文校准的 `craft_ratio` 分布为 A 组 0.87–1.00、B 组 0.33–0.53、C 组 0.00–0.27。**0.53 与 0.87 之间没有任何观测。** 现行门限 `CRAFT_GATE_RATIO = 0.6` 与 `CRAFT_OVERALL_GATE_RATIO = 0.3` 落在这个空洞里，位置无实证支撑。

## 3. 目标带位阶梯

**`[0,100]` 的完整划分，不留任何空洞。** 这是硬约束：任何没有产出者的分数段都是缺陷——
现行 0.6 阶梯有三段空洞（`0–44`、`60–67`、`95–100`），正是本次要消掉的东西。

| 带位 | 分数区间 | 整数分 | 准入条件 |
|---|---|---|---|
| **S** 传世 | 95 – 100 | 6 | 缺陷天花板 = A 且 craft 天花板 = A 且四席锚文对照一致指向 S |
| **A** | 80 – 94 | 15 | 零 veto/core 缺陷 + craft 达门 |
| **B** | 60 – 79 | 20 | 有 core 缺陷，工艺证据尚可 |
| └ **记录型**（B 子级） | 60 – 67 | 8 | craft 天花板封顶，正向工艺证据不足 |
| **C** | 40 – 59 | 20 | 高严重度 veto 命中 |
| **忠实失败区** | 0 – 39 | 40 | 忠实带 = C（文中有说法与来源矛盾） |

带位词表新增 `S`；`记录型` 仍是 `B` 的子级，只影响窗口与注记。

### 3.1 忠实度：C 改为投影，不再钳位

现行忠实度是**钳位**（`忠实 B → min(总分,75)`、`忠实 C → min(总分,45)`），两个值恰好等于
旧 B、C 窗口的下界。钳位在新阶梯下会制造新的空洞：忠实 C 若钳到 39，就只产出 39 这**一个点**，
`0–38` 仍然无人认领。

因此忠实 C 改为**投影**——把文学定位铺进 `[0,39]` 整个区间：

| 忠实带 | 现行 | 新 | 理由 |
|---|---|---|---|
| A / N/A | 不动 | 不动 | — |
| B | 钳位 ≤ 75（旧 B 下界） | 钳位 ≤ 60（新 B 下界） | 60 在 B 带内、另有产出者，不造成空洞 |
| C | 钳位 ≤ 45 | **投影进 `[0,39]`** | 唯一能让整段有主的做法 |

语义也更准：与来源矛盾的文本一律出局，但**写得好的出局与写得烂的出局仍然可分**
（文学定位 0.90 → 35.1；0.50 → 19.5；0.10 → 3.9），信息不丢。
这是语义变更，`SKILL.md` 第 7 节第 5 条的封顶条款需同步改写。

## 4. 机制设计

### 4.1 S 的可判别信号：启用已有的锚文对照通道

席 04–07 已在读 `references/anchors/band-{a,b,c}.md` 并输出 `anchor_comparison.placement`，当前只进人工仲裁区、不参与带位。

改动：

- 新增 `references/anchors/band-s.md`，规格同现有锚文（纯合成校准材料，不携带本轮期望带位）
- `PLACEMENT_RANKS` 扩充 `接近S = 4.0`
- **升 S 条件**：缺陷天花板 = A 且 craft 天花板 = A 且四席 `placement` 一致指向 `接近S`
  **且无素读者传播意愿预警**
- 四席不一致则停在 A，分歧按现有 ≥2 档背离机制进仲裁区
- 预警一票否决 S 的理由：预警的触发条件是素读者对「你愿意把这篇讲给别人听吗」答
  「不愿意」，而「传世」的字面意思就是**会被传下去**。一篇被提名传世、素读者却不愿
  转述的文本，是定义上的自相矛盾，不只是待核的疑点。不新增带位字符串——预警仍然
  只做一件事（`A` → `A候选（待人工确认）`），S 只是多要求一条「无预警」。

`seat-output.schema.json` 的 `verdict` 枚举不动，判据表判定语义不动。**评审席仍不产生任何数字**——承重原则未破。

### 4.2 A 带死区：两处独立修改

**(a) `defect_density` 分母剔除该带位下不可能失败的判据。** 分母改为只统计非 craft 的 extended 判据。效果（A 窗口 `[80,94]`）：利用率 27% → 64%，可达整数分 5 个 → 10 个。

**(b) `placement` 按带位自身可达区间做 min-max 归一化。** 这是唯一能打满窗口的改法。效果：利用率 → 100%，可达整数分 → **15 个**（A 带 80–94 全部可达）。

归一化常数**不硬编码**，由判据表（tier / craft set / 权重）解析导出，并由契约测试锁定：判据表一改即重算，漂移即报警。

### 4.3 席 05 craft 门死码

**不改判据归属**（见 1.3 第 2 条：解耦会降低分辨率）。改门的算法：`craft_ratio` 的门只对**未被 core/veto 强制的成员**计算。

- 席 04 → `{TW2, SC1}`
- 席 05 → `{P7}`
- 席 06 → `{L5, L7, TW3}`（不变）
- 席 07 → `{E6, E7, TW14}`

带内定位仍使用完整 craft set。门的语义改变后阈值必须重标定，不得沿用 0.6。

### 4.4 辅助维度改报原生读数，不再给 0–100 分

记分卡此前把七个维度并列，但其中只有四个是带位窗口投影、彼此可比；另外三个各有各的
临时刻度，混在一起暗示了并不存在的可比性。三者在新阶梯下还会读出错误的带位：

| 维度 | 全部可能取值 | 新阶梯下读作 |
|---|---|---|
| AI 洁净度 | `{100, 97, 94, 91, 90}` | **恒为 S** |
| 读者体验 | `{85, 75, 65, 55, 45, 35, 25}` 及其均值 | 满分 85 落在 A |
| 忠实度维度分 | `{90, 65, 45}` | 忠实 A 读作 S |

**改为按原生单位呈现，记分卡分成两组：**

```
带位维度（同一把尺，可比）
  结构 88   人物 94   语言 85   情感 88

诊断维度（各自的尺，不可与上组相比）
  AI 痕迹   检出 2 处（轻 2 / 重 0）
  素读者    2 位，共 1 处不适；无传播意愿预警
  忠实度    A（无无支撑断言）
```

信息不丢，反而更具体；同时一次性消掉三个按旧阶梯标定的常数。需改
`derived-report.schema.json` 与报告模板。

**仍需重映射的常数**（回退链专用，见下）：

| 常数 | 现值 | 位置 | 处置 |
|---|---|---|---|
| 忠实 B 总分封顶 | 75 | `derive_report.py:533` | **→ 60**（新 B 下界），见 §3.1 |
| 忠实 C 总分封顶 | 45 | `derive_report.py:531` | **→ 改为投影进 `[0,39]`**，见 §3.1 |
| 无维度诊断基线 | 50 | `derive_report.py:38` | 见 §4.5 |

### 4.5 回退链：一个由 §4.4 引出的未决问题

`SKILL.md` 第 7 节有一条硬性条款：**只要阶段三成功生成报告，就必须输出 0–100 数值总分**，
不得因降级执行、覆盖缺口或引文作废而清空。文学带为 `N/A`（04–07 未全覆盖）时，
总分依次回退到读者体验 → AI 洁净度 → 忠实度 → 固定基线 50。

§4.4 取消这三个维度的分数后，**回退链失去了输入**；而且这些代理值本身在新阶梯下就
读错了带位（AI 洁净度回退会给出 90–100，读作传世）。新阶梯是 `[0,100]` 的完整划分，
没有留出「未知」区，所以任何回退值都会被读成某个带位。

需要定夺（阶段 2 开工前）。倾向：文学带 `N/A` 时报告已经是
`formal=false` + 带位「未形成」+ `status=provisional`，此时**总分应是一个不可能与
带位派生分混淆的单一诊断值**，并在报告中明确标注其性质；代理值不再参与总分。
代价是丢失「有读者覆盖」与「完全无覆盖」之间的区分度——若认为该区分度必须保留，
则需要为回退单独划一个不与带位重叠的表示法（例如不给数字而给状态码），
但这会与上述硬性条款冲突，需同时修订 `SKILL.md`。

## 5. 评分格深模块化

### 5.1 现状：12 个浅函数瓜分一个无名 blob

`list[tuple[dict, dict, dict]]` 由 `main()`（258 行）内联拼装，被 12 个函数用位置下标各自重新过滤（`row[0]/row[1]/row[2]` 出现 17 处）。带位与带内定位的耦合不属于任何模块。

**这个浅设计已造成一次实际损失**：「A 带内哪些分数可达」无法向任何接口提出，因此 §1.1 的死区穿过了整个校准门禁——门禁把 window-hit 与 separability 降级为 informational，理由写的是「true by construction」，而它们恰恰在反方向上成立。

### 5.2 目标形状

```python
lattice = BandLattice(rubric)

# 只依赖规则，不需要任何文本
lattice.reachable_range("A")          # -> (lo, hi)

# 依赖规则 + 本轮判定
lattice.band(jv.formal())             # 正式带位：只认引文核验通过的
lattice.position(jv.frozen(), seat)
lattice.score(jv.frozen())            # 评分：认冻结全量
```

**决策 1 —— 接缝：`rubric` 构造 + `judgments` 查询。** `reachable_range` 只依赖评分规则、与具体文本无关；把 `rubric` 提到构造时，这个问题才成为可提问的。IO 留在接缝之外，模块离开文件系统也可测。

**决策 2 —— `rubric` 真源：判据表。** craft set 在四张判据表中改为**结构化声明**（表格，非散文句），`parse_criteria` 一并解析，删除 `derive_report.CRAFT_SETS` 常量。判据表成为「哪些判据、什么 tier、什么极性、是否正向工艺」的唯一真源。窗口/权重/阈值等公式标定常数仍在代码，留待后续独立处理。

**决策 3 —— 引文作废的二元性显式化。** 当前 `valid`（引文核验通过的子集）与 `judgments`（含作废项的冻结全量）喂给同一批函数，产出两个可能不同的带位，而这个关系在代码里完全隐式。

`JudgmentVector` 自己持有 `invalidated` 集合，导出两个具名视图：

- `.formal()` —— 正式带位用，排除 `receipt["invalidated_criteria"]`
- `.frozen()` —— 评分用，冻结全量

不变量（单向，非等价）：`band(jv.formal())` 不严于 `band(jv.frozen())`；存在作废项时 `scores.status` 必须为 `provisional`。
作废项未必触及天花板，两个带位**可以相同**——不得断言二者必然不等。

### 5.3 `reachable_range` 算法

**实现见 `band_lattice.BandLattice.reachable` / `.seat_states` / `.verify`（阶段 1 已落地）。**
本节的初稿描述与最终实现有出入，以下是实际做法。

逐席穷举真实判据子集（`2^n`，最大席 13 条即 8192 次，四席合计约 2.6 万次，
0.04 秒），约简到四元组 `(craft_ratio, defect_density, 含高严重度 veto, 含 veto/core)`：

```
每席约简状态：席04 136 / 席05 74 / 席06 64 / 席07 89
约简状态笛卡尔积   57,324,544     ← 直接枚举不现实
```

不直接枚举笛卡尔积。关键性质：**`placement = 0.7·mean(pᵢ) + 0.3·min(pᵢ)`
对每个 `pᵢ` 单调**，因此只要约束在各席之间可分离，逐席独立取极点即为全局极值。

带位条件只透过 `(craft_ratio, 含高严重度 veto, 含 veto/core)` 三元看每一席，
于是把每席的状态按这个三元**分组**（12–14 组），组内预先取 `p` 的极大与极小：

```
分组笛卡尔积       26,208         ← 实际枚举量，毫秒级
```

对每个分组组合判定带位（`craft_ceiling` 的均值门与 `defect_ceiling` 的存在量词
在此都已被组合固定，因此可精确判定），命中目标带位者取组内极值算 `placement`，
在全部命中组合上取 min/max。**结果是精确的，不是采样或近似。**

3. **求出的每个极值点回灌真实的 `band_detail()` 与 `placement()` / `project()` 复算**
   （`BandLattice.verify`）。模型说某配置在某带位得 X 分，就把见证还原成真实判定行
   让真函数跑一次；对不上即报错。

第 3 步是本设计的核心保障：**可达性模型不允许与实现各说各话**——这正是死区当初
逃脱门禁的机制。四个带位的极值点当前全部回灌通过。

**范围限定**：全判定配置（每条判据均为 YES/NO）。`ABSTAIN`/`NA` 会缩小
`defect_density` 的分母、把密度推向极端，真实区间只会更宽不会更窄；该限定随
`reachable` 的结果一起写入账目的 `scope` 字段，不得隐去。

## 6. 自洽性门禁

机械、闭合、可失败。作为契约测试常驻。

1. 每个带位的 `reachable_range(band)` 必须等于文档声明的窗口；不等时文档必须显式记录差额（禁止沉默）。
2. 每个对外展示的分档标签必须至少有一个可达分数，否则报错。
3. 判据表解析出的 craft set 与代码中的任何副本必须一致（§5.2 决策 2 落地后自动成立）。
4. `formula_version` 必须与 `SKILL.md` 中声明的版本一致。
5. `reachable_range` 的每个极值点回灌真实 `band()`/`score()` 验证通过。

**门禁在阶段 1 首次运行时必然失败**——它会报出 §2 表中第 1、2、3 条。这是预期结果，不是缺陷：门禁的首次运行即诊断报告。
