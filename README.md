# lit-panel（文学评审团）

*An eleven-seat, mutual-blind literary review panel for Chinese memoir / narrative text — a Claude Code / Codex skill.*

![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg) ![Version: 0.4.1](https://img.shields.io/badge/version-0.4.1-lightgrey.svg)

对同一篇中文回忆录/叙事文本，十一个评审席各自独立阅读、互不可见彼此结论，由编排逻辑做显式规则合成——输出带位、逐字证据，以及从判据向量机械导出的多维评分（评审席本身零打分，分数是导出视图，不是评审席的判断）。

## 为什么存在

给一篇回忆录章节打「7.5 分」看起来客观，实际上是把无数个不可通约的判断压缩成一个虚假的精确数字——换一次问法、换一个模型，这个数字往往就会漂移，却不会告诉你这篇文章哪里好、哪里坏、谁说了算。

不用数值分不是审美偏好，是有依据的选择。本项目多条判据（席04/05/06/07/09 的 TW 系列）转译自 **TTCW**（Torrance Test of Creative Writing）——TTCW 本身评估创意写作质量时，用的就是一组由专业作家逐条回答的二元判据，而不是一个连续分数；它的原始研究还测试过用大模型自己来当 TTCW 评审，结论是模型评审与专业作家评审员的判断经常对不上号。数值分数会把这种「对不上号」悄悄压平成一个看起来确定的数字；lit-panel 选择保留分歧，而不是压平它。

lit-panel 的应对方式是放弃刻度本身，只产出三样实的东西：

- **判据**——这一条具体、可观察的行为是否成立；
- **证据**——支撑判定的逐字引文，经机械核验，查无此文的判定直接作废；
- **带位**——A/B/C 三档定性归类，而非连续刻度。

报告的最终产物是**带位（A/B/C）+ 逐字引证 + 分歧区 + 修订包 + 判据向量机械导出的多维评分**（v0.4.0 起新增）。**评审席本身零打分**——3.4 节输出契约没有变过一个字，评审席不产生、也不需要意识到任何数字；分数是判据向量的一个公开公式导出**视图**，全文可复现（见 `SKILL.md` §5.8），反对的从来不是"报告里出现数字"本身，而是模型凭印象报出一个**伪精确**的数字（说不清"7.5 分"从何而来、换一次问法就漂移）。带位仍是定性结论，分数是同一份判据证据的另一种呈现，两者不矛盾、也不互相替代。

## 核心机制

本节是面向使用者的精简版机制说明。完整的运行时权威是 `skills/lit-panel/SKILL.md`（两个分发平台共用的唯一编排逻辑）；构建期规格见 `docs/DESIGN.md`，两者冲突时以 `SKILL.md` 为准。

### 十一席评审团

| 席位 | 方向 | 激活条件 | 带位角色 / 特殊权限 |
|---|---|---|---|
| **01** `lit-fidelity` | 只认来源：claim 抽查回溯，五态标签（SUPPORTED/PERMISSIBLE_INFERENCE/UNSUPPORTED/CONTRADICTED/UNVERIFIABLE） | 提供 `--source` 时 | 忠实带唯一来源；红线否决权 |
| **02** `lit-continuity` | 文本内自洽：时间/人物/事实/规范一致性 | 总是 | 证据席；确证矛盾时有红线否决权 |
| **03** `lit-slop` | AI 特有痕迹：对照模式库做 span 标记，分轻/重 | 总是 | 证据+特征席；无否决权 |
| **04** `lit-structure` | 叙事结构：场景/概述、铺垫回应、章法 | 总是 | 文学带核心席 |
| **05** `lit-character` | 人物与心理：动机连续、对话口吻、拒绝粉饰 | 总是 | 文学带核心席 |
| **06** `lit-prose` | 语言与节奏：声音一致、承接、词语精度 | 总是 | 文学带核心席 |
| **07** `lit-resonance` | 情感与抵达：processed vs lived、拒绝情感硬推 | 总是 | 文学带核心席 |
| **08** `lit-naive-reader` | 素读者：读前无判据，纯体验报告，读后补测 | 总是（严格分两步执行） | 参与合成判断，不入判据向量；判据后测制 |
| **09** `lit-originality` | 原创性与陈套：人类写作意义上的套路、个性色彩 | 总是 | 加分维（v0.4.1起不入带位，问题判定降为打磨建议） |
| **10** `lit-brief` | 编辑意图：brief 要素落实、戏剧目的达成 | 预设范围含10 且提供 `--brief` 时 | 不入带位；未达标转修订项 |
| **11** `lit-ethics` | 他者与伦理：单方转述定性、隐私必要性、弱者尊严 | 回忆录默认开启（`custom` 显式排除时报告仍会警示） | 不入带位；发现一律转人工仲裁 |

**预设分档**：`quick`=01,02,03,08；`standard`=01–09+11（不含10；提供 `--brief` 时10自动并入，无需改用 `custom` 显式列出）；`full`=01–11（01/10 若因缺输入未激活，会在报告"跳过席位及原因"处以**警告**级别标注，因为 full 的显式意图是启用全部十一席）；`custom(<列表>)`=从上表任选席位号，语法如 `--preset custom(01,03,08)`，编号必须已在 `registry.md` 注册，否则视为参数错误直接中止。条件激活席在条件不满足时自动跳过，并在报告头部注明原因。

### 三阶段流程

```
输入：被评文本 + 可选 --source（来源素材）/ --brief（编辑意图）
        │
        ▼
阶段零 · 机械预检 —— 致命失败网关：文本截断/未收束 → 直接中止，不开席；
                      另做元数据剥离、体裁判断、brief 硬性约束机械核验
        │
        ▼
阶段一 · 互盲并行评审 —— 十一席各自独立阅读、独立套用自己的判据文件，
                          互不可见彼此的结论（席08额外分两步：读前无判据 → 读后追问）
        │
        ▼
阶段二 · 引证机械核验 —— 逐字核验每条 quote 是否确实出自原文；
                          查无此文的判定直接作废（作废机制）——
                          这是防止一条编造引文"注毒"证据链、让错误判定蒙混过关的防线
        │
        ▼
阶段三 · 显式规则合成 —— 红线区/判据向量/带位/评分导出/分歧区/
                          人工仲裁区/决策建议/修订包，机械汇总，不做二次审美裁决
        │
        ▼
输出：结构化评审报告 + 判据详表侧车
     （references/report-template.md 结构 + `<报告名>-details.md`）
```

`--stability` 在阶段三之后追加一轮独立复跑并做判据级翻转率对比；`/lit-compare` 走独立的对比模式（见"参数参考"），不复用阶段三的带位/决策矩阵。

### 三层判据带位

忠实带（席01）与文学带（席04/05/06/07）各自基于自己的判据集合定级，互不合并成一个总带位。

文学带的判据分三层：

- **veto**——该席最致命的 ≤2 条核心判据，命中即代表该维度结构性坍塌。例如席07（情感）选满2条：情绪完全没被戏剧化、只被叙述者宣布 / 情绪被强行戏剧化到失真——这两个对称极端任一命中都代表本章情感处理从根本上失败。逐席清单与选择理由见 `criteria/CHANGELOG.md` v0.2.0 节。
- **core（普通）**——该席 core 判据表中除 veto 外的其余判据。
- **extended**——补充判据，不参与带位判定，但仍照常评审、进判据向量。

带位判定按优先级从上到下，第一条命中即停：

1. 存在 veto 问题判定且 severity=**高** → 文学带封顶 **C**；
2. 存在 veto 问题判定但 severity=中/低 → 最高只到 **B**（不触发C），且额外列入人工仲裁区；
3. 不满足1、2，但普通 core 判据存在任一问题判定 → 最高只到 **B**；
4. veto+core 全部通过 → **A候选**——候选不等于确定，还需通读 `anchors/band-a.md` 确认候选文本质感与锚点样例相当，明显不及则降级为 B。

**severity 不是描述性装饰，是直接改变机械结果的四处开关**：

1. 忠实带阈值——只有 severity=高的 UNSUPPORTED 才触发忠实带 C 封顶，仅 severity=低的问题只封顶到 B；
2. 红线区准入——只有 severity=高的席01 UNSUPPORTED、席02"确证矛盾"NO 才进红线区；
3. veto 分档——同一条 veto 判据的问题判定，severity=高封顶C，severity=中/低只到B且转人工仲裁；
4. 修订包排序——severity（高/中/低）是修订会话优先处理顺序的依据，但不换算成分数。

### 原创加分（席09，不入带位）

v0.4.1 起，席09（原创性与陈套审读）退出上述 veto/core 三层带位体系——不扣分、不封带。席09照常评审（判定+引文+自由观点不变），但判定结果只驱动总分的**加分**，机械规则见 `SKILL.md` §5.8：

- O 系通过类判据（O2/O3/O5/O6）**全部** YES 且零 O 系问题判定 → 总分 **+5**；
- 通过类 ≥3 条 YES 且零问题判定 → 总分 **+3**；
- 其余情况（含任何 O 系问题判定）→ **+0**，**任何情况下不扣分**。

问题判定（如 O1 命中被用滥的比喻）降级为可选打磨建议，进报告"问题与修订建议"区与"评委分论"，不静音、不影响带位。这一变更的产品立场：原创性对回忆录体裁而言是锦上添花，不是核心义务——一段平实但真实的人生经历仍是合格的回忆录，不该因缺乏文学新意而被拖累带位（理由详见 `criteria/CHANGELOG.md` v0.4.1 节）。

### 素读者报警器

当四个文学带核心席的 veto+core 判据**全部通过**、本应产出 A 候选时，额外检查一件事：素读者（席08）读后第四问——"你愿意把这篇讲给别人听吗？"（只接受"愿意"/"不愿意"，不接受"看情况"之类模糊作答）。

- **N=1**：答"愿意" → A候选照常成立，继续走锚点对照。答"不愿意" → 触发报警：**不自动发A，也不因此降级**，决策建议改写为"**A候选（待人工确认——判据与读者感受分歧）**"，强制转入人工仲裁区。
- **N>1**：以过半数读者的"愿意/不愿意"作答为准；平局按"不愿意"处理——宁可多触发一次人工核对，不静默放行。
- 报警器只在"零 core 问题判定"这个前提下才有意义——若判据面已经因 veto/core 问题判定把带位封顶到 B 或 C，素读者答"不愿意"不再单独触发额外仲裁，因为问题已经被判据面捕捉。

它替代的是已废弃的 v0.1.1"素读者正向参与A候选条件"设计。旧设计让素读者直接参与 A/B/C 判定本身；新设计里素读者不参与带位判定，只在判据"看起来全过"时充当最后一道读者感受校验——判据与读者体验一旦分歧，交给人工，不交给机制自己拍板。

### 互盲与反偏差设计

- **换序双评（仅 `/lit-compare`）**：对比模式下每席对 A/B 做两次偏好判断——一次按 (A,B) 顺序呈现，一次按 (B,A) 换序呈现。两次都偏好同一篇 → 记录该席偏好；两次随呈现顺序反转 → 记 **TIE**。这是专门用来侦测"评审只是在偏好呈现顺序"这种位置偏差的设计，输出只给分布计数，不换算成总比分或加权名次。
- **并行路径的结构性隔离**：Claude Code 下，十一席是并行 Task 子代理，上下文天然互相隔离，互盲是结构性保证。
- **顺序路径的显式声明遗忘**：Codex 没有并行能力，主会话依次扮演每一席时，必须在换到下一席前显式声明"本席评审到此结束，丢弃本席全部结论"，用明确指令让模型主动模拟遗忘——因为顺序执行时对话上下文实际上是连续的。这条声明不是客套话，是互盲纪律在无并行环境下唯一的落地方式（仍是模拟，细节见下文"已知边界与风险"）。
- **跨家族评审建议**：若生成方与评审方用同一模型/同一会话，报告头部"模型与会话披露"字段须如实标注，并建议跨家族评审（如 Claude 生成 → Codex 评审，或反之）以降低"同一套潜在偏见既写又判"的同源盲区。
- **自由观点字段**：每席输出契约里除判据表外还有一段"自由观点"（1-3段不受判据束缚的专业直觉）。连同素读者的"读前无判据"机制，这是判据表之外仅有的两处不能靠"背题"绕过的表达空间——详见下文 Goodhart 风险讨论。

## 安装

### Claude Code（插件形态）

三种方式，按需选用：

```bash
# 方式一：手动放入本地 skills 目录（下次启动 claude 时自动加载为 lit-panel@skills-dir）
cp -r /path/to/lit-panel ~/.claude/skills/lit-panel
# 也可以用软链接，方便跟随仓库更新：
ln -s /path/to/lit-panel ~/.claude/skills/lit-panel
```

```bash
# 方式二：注册为本地 marketplace 后安装（持久生效，另一条官方支持的路径）
# 本仓库根目录已含 .claude-plugin/marketplace.json，无需自建。
claude plugin marketplace add /path/to/lit-panel
claude plugin install lit-panel
```

已在隔离 `HOME` 环境实测跑通（`HOME=$(mktemp -d) claude plugin marketplace add ...`），两条命令依次输出：

```
✔ Successfully added marketplace: lit-panel (declared in user settings)
✔ Successfully installed plugin: lit-panel@lit-panel (scope: user)
```

`claude plugin details lit-panel` 可确认组件清单：3 个 skills（`lit-panel`/`lit-review`/`lit-compare`）+ 11 个 agents，与源码目录结构一致。若你的本地 marketplace 注册名与插件名不同（比如你 fork 后改了 `marketplace.json` 里的 `name`），用 `claude plugin marketplace list` 确认注册名，再 `claude plugin install lit-panel@<注册名>` 安装。

**实测发现的一个细节**：装为 plugin 后，`claude plugin details` 列出的 agent 组件名是**文件名**（如 `ethics-reviewer`），不是 agent 定义文件 frontmatter 里的 `name` 字段（如 `lit-ethics`）——`SKILL.md` §3.3 的"派发降级规则"就是为这种情况准备的：若按 `registry.md` 的 agent name 派发 Task 子代理失败，改用平台实际列出的标识符重试。

```bash
# 方式三：单次会话临时加载（不做持久安装，适合先试用）
claude --plugin-dir /path/to/lit-panel
```

安装完成后，`/lit-review`、`/lit-compare` 两个命令即可用，十一位评审席作为 subagent 由 Claude Code 原生并行调度。

### Codex（skill 形态）

```bash
# 推荐：用安装脚本（会检测已存在安装并询问是否覆盖，默认不覆盖）
./scripts/install-codex.sh

# 或手动复制
cp -r skills/lit-panel ~/.agents/skills/lit-panel
```

**新装技能在当前会话不会自动被发现**：Codex 只在会话启动时扫描技能目录，已打开的会话不会重新扫描。安装完成后若想立刻使用，两条路径二选一：重新开一个 Codex 会话；或者不依赖技能自动发现，直接让 Codex 按绝对路径读取 `~/.agents/skills/lit-panel/SKILL.md` 并按其内容执行。

Codex 没有 Claude Code 那样的原生并行 subagent 机制，因此十一席评审在 Codex 下由 `SKILL.md` 编排**逐席顺序执行**——互盲语义力求等价（每席仍是独立、互不可见彼此结论的上下文），但如下文"已知边界与风险"所述，这是尽力模拟，不是真正的上下文隔离。

## 快速开始

```bash
# 单文评审：标准预设（01–09+11），并提供访谈素材激活席01忠实审读
/lit-review 章节.md --source 访谈.md --preset standard
```

```bash
# A/B 对比：两篇同源同任务的文本，十一席默认对比评审，每席换序双判
/lit-compare a.md b.md
```

报告长什么样：一份 `/lit-review` 报告（v0.4.0 起报告层重构）固定包含八个区块，**区块标题不带编号，物理顺序即阅读顺序**——总评（评委会综述文风，2-3段）、红线警报（仅有 source 且触发时出现，紧随总评之后、总分卡之前）、总分卡（总分/等级/一句话判语，机械导出）、多维评分表（文学四维+原创加分维+AI洁净度+读者体验，有 source 时加忠实度）、评委分论（每席一段真实评委口吻短评，问题判定引文行内织入，禁表格）、问题与修订建议（原修订包 prose 化）、需人工裁决（仅有内容时出现；每类都是叙述条目——谁与谁、各自立场、为什么需要人来裁，不出现判据表）、评审档案（原头部表格精简版）——结构固定，不因文本长短或问题多少而增删。全量分席判据表、阶段二核验逐条记录、需人工裁决区的原始判据表，均**不内联主报告**，移入侧车文件 `<报告名>-details.md`，评审档案给出指针。完整结构见 `skills/lit-panel/references/report-template.md`。`/lit-compare` 走独立的对比输出结构（各席偏好+理由+全团分布），不复用这套带位/评分/决策体系。

## 参数参考

| 参数 | 取值 | 说明 |

## 性能预期

以下是实测得到的耗时参考（非承诺，实际耗时受文本长度、模型、网络与并发限流影响）：

- **Codex（xhigh 推理档）**：`quick` 预设（4 席顺序执行）约 10 分钟；`standard` 预设（10–11 席顺序执行）约 30–45 分钟——顺序路径每席都是一次完整的模型调用，耗时随激活席位数近似线性增长。
- **Claude Code（并行 subagent）**：`standard` 预设约等于**最慢单席**的耗时（5–8 分钟），因为十一席是同批并行 Task 调用，总耗时由最慢一席决定，不是逐席累加。

**建议**：

- 迭代轮（改一稿、看一眼问题）用 `quick`；门禁轮（发布前终评、正式交付判断）用 `standard` 或 `full`——不要为了省时间在门禁轮降档，`quick` 甚至不含任何文学带核心席，产出的带位判定基础不完整。
- Codex 顺序路径下，评审席本身的推理强度可以用 `medium` 档而非 `xhigh`——判据表作答是结构化的逐条核验型任务，不是需要高强度推理的开放式创作，medium 档通常够用，能显著压缩顺序路径下逐席累加的耗时。
- `--source` 只传与本章直接相关的转写/素材，不要整批传入无关章节——来源侧引文核验（3.4/4 节）需要在这批素材里查找引文，素材越大核验越慢，且不相关素材不会提高忠实带判定的准确度。

**v0.3.0 性能优化的预期效果（估算，待实测）**：本版新增的引证义务分级（多数判据的通过判定不再强制附引文）与顺序路径正文单贴优化（Codex 路径正文只在会话开头贴一次，不再逐席重贴）预计能把 Codex `standard` 顺序路径的耗时从约 30–45 分钟压缩到 **15–20 分钟**左右。这是根据两项优化各自节省的 token/调用量做的估算，尚未经过端到端真机计时验证，实测数字确认后应更新本节。

## 报告解读

一份报告严格按 `references/report-template.md` 的结构组装（八个区块，见上文"快速开始"，区块标题不带编号，物理顺序即阅读顺序）。以下是每个区块该怎么读，以及分数从哪来。

**分数从哪来**——评审席从始至终**零打分**：3.4 节输出契约只有 verdict/quote/location/severity/note，没有任何数字字段。总分卡与多维评分表里的每一个数字，都是 orchestrator 在阶段三对判据向量套用 `SKILL.md` §5.8 的确定性公式**事后机械导出**的——文学四维（结构/人物/语言/情感）各自基准 90 分，veto 判据问题判定按严重度封顶（高→≤45，中/低→≤65），普通 core 判据每条问题判定 −12，extended 每条 −5；AI洁净度（席03导出）、读者体验（素读者R系列导出）、忠实度（有 source 时，取自忠实带字母）三维公式各自独立；总分=文学四维简单平均，再叠加席03修正（−3/条，上限−10）、**原创加分**（v0.4.1新增——席09 O系通过类判据全部YES且零问题判定→+5，≥3条YES且零问题判定→+3，其余含问题判定→+0，只加不减）与忠实带总分封顶（忠实带C→总分封顶45且决策强制为"重写建议"；忠实带B→封顶75，均在加分之后仍生效）。公式全文公开，任何人都能拿判据向量重算一遍验证——这正是"证据驱动"和"凭印象打分"的区别：反对的不是数字，是说不清来路的数字。总分卡本身用二级标题+加粗呈现（如"## 总分：45/100 · C"），报告全文只有一个一级标题。

**带位含义**——带位是与分数并行的两条独立定性轨道，不合并成一个总分，也不由分数反推：

忠实带（完全基于席01五态分布，未提供 `--source` 时记 N/A，此时多维评分表不出现忠实度行）：A=五态分布完全干净；B=不存在 CONTRADICTED、且不存在 severity=高的 UNSUPPORTED，但存在 severity=中/低的问题，或只有 PERMISSIBLE_INFERENCE/UNVERIFIABLE 而无 UNSUPPORTED/CONTRADICTED；C=存在 CONTRADICTED，或存在 severity=高的 UNSUPPORTED。

文学带（基于席04/05/06/07的 veto/core 判据；`quick` 预设不含任何文学带核心席时不产出该带位。席09原创性 v0.4.1 起不参与本带位，改走独立的"原创加分"，见上文"原创加分（席09，不入带位）"）：分级规则见上文"三层判据带位"；此外还有一个特殊状态——"**A候选（待人工确认——判据与读者感受分歧）**"，即素读者报警器触发时的输出。两条带位若同为 N/A（如 `quick` 预设且未提供 `--source`），决策建议改为"**仅诊断**"，只列出本轮问题判定供参考，不输出矩阵缺省值冒充真实决策，总分卡此时也不产出常规分数。

**红线警报**——来源只有两处：席01判 CONTRADICTED 或 severity=高的 UNSUPPORTED；席02 severity=高的"确证矛盾"NO 判定。有 source 且触发时，本区在总评之后、总分卡之前出现，成对引文（判定引文+来源/对照引文）。红线区非空不代表报告到此为止——其余全部区块仍照常完整产出，总分卡也仍会正常出现（忠实带C时总分已按规则封顶45）。

**评委分论怎么写出来的**——每席一段，素材只能来自该席自由观点/素读者体验报告的节选与微编辑，问题判定的引文以行内引用织入行文，不允许合成层自己新增任何这些素材里找不到出处的评价——分论是"编辑"不是"评审"，这条硬规则见 `SKILL.md` §5.9。

**需人工裁决（原分歧区+人工仲裁区合并呈现，仅有内容时出现）**——本区**全面禁止表格**，每一类都写成叙述条目：谁与谁、各自立场一句话、行内「」引文、为什么需要人来裁（原始判据表移入详表侧车"人工裁决区详表"节，本区末尾给指针）。分歧：同一文本区域上"问题判定"与"通过判定"并存，或某席自由观点显式反对另一席结论，都算分歧，**不平均、不加权、不裁决对错**，双方立场原样并列叙述，留给人工/编辑判断。人工仲裁：以下几类判定永远不会被自动放行或自动阻断——

1. 全部 ABSTAIN 判定（含"NA 但无适用性理由"降级而来的 ABSTAIN）；
2. 席11（他者与伦理）的**全部**判定，无论 verdict 为何——伦理发现不自动放行也不自动阻断；
3. 阶段二机械核验失败、被作废的判定（附作废原因，供复核是否为核验本身的误判）；
4. veto 判据的问题判定且 severity=中/低（严重度判断本身直接影响带位，需要人工核对）；
5. veto 判据的 NA（NA 仍需附适用性理由，无理由按 ABSTAIN 处理，归入上面第1类；veto 判据对带位有直接封顶/仲裁后果，NA 意味着这层判断缺失）；普通 core/extended 判据的 NA（带理由）不在此列，正常呈现在详表侧车，不升级到本区；
6. 素读者报警器触发记录。

以上任一类均为空时，本区整节不出现，不留占位空标题。

**问题与修订建议怎么喂回生成会话**——汇总红线区条目 + 判据向量中全部"问题判定"，每条＝位置+行内引文+为什么+怎么改，按 severity 排序，编号沿用判据 id，可以直接整段贴进下一轮修改会话当作任务清单。同一处文本被多条判据命中时，只生成一条合并任务（severity 取最高值，修改建议合并），避免同一处文本在清单里重复出现好几次。**人工复核提示**：机械核验只保证引文真实存在于原文，不保证引文真的支撑该条判定的论断——本区底部会附一句提示，建议逐条人工复核一遍再执行。

**评审档案与详表侧车**——原头部表格的精简版，含文本名/预设与激活席位（跳过席位并入一句话）/模型与降级披露/核验统计/规则版本，以及详表侧车文件路径指针。全量分席判据表+阶段二核验逐条记录+需人工裁决区原始判据表均不再内联主报告，在侧车 `<报告名>-details.md` 里，结构沿用旧版"分席判据表汇总"格式并追加"人工裁决区详表"节。未提供 `--source` 时，本区追加一行"本轮未提供 --source，未做事实核查，评分仅反映文本内在质量"——这是 v0.4.0 起忠实性免责声明的唯一出现位置，不再是标题下的强制整行警示横幅（总分卡本身在无 source 时也会用小字呼应同一件事，两处已经足够）。

## 自定义与扩展

**判据文件可编辑**：`skills/lit-panel/references/criteria/*.md` 里每条判据的措辞可以打磨，但不能改变其语义与极性（`[通过]`/`[风险]`）——改语义等于改评审标准本身，需要走下面的扩席/CHANGELOG 流程，不是随手改改措辞就够。

**淘汰记 CHANGELOG**：判据的取舍、替换、废弃都要记入 `skills/lit-panel/references/criteria/CHANGELOG.md`，一行一条，写明原因。v0.2.0 是一个可参照的实例——记录了五个文学带核心席各自划出 ≤2 条 veto 判据的选择理由，以及一次通读全部 11 个判据文件、逐对复核语义重叠是否超出准入线的审计结果。

**私有判据（`criteria/99-private.md` 模式）**：判据文件全部随包公开分发。如果需要恢复"暗考题"效果（生成方无法提前得知的额外判据），可以自建 `skills/lit-panel/references/criteria/99-private.md`（或类似命名），加入你自己的 `.gitignore`（不随仓库分发、不进公开判据池），再按下面"扩席"的操作步骤挂载为一个新席位，或并入既有席位的判据文件。这是本地环境的可选加固，lit-panel 本身不预设任何私有判据内容。

**扩席（开一整个新评审席位）**：三件套同步动作，缺一不可——

1. 在 `registry.md`「席位表」追加一行（agent 文件 / agent name / 判据文件路径 / 方向一句话 / 激活条件 / 带位角色 / 特殊权限，8 列不留空）；
2. 新增一个 `agents/*.md` 席位定义文件；
3. 新增一个对应的 `criteria/*.md` 判据文件，并在 CHANGELOG 记录取舍。

开新席前须先过「准入四条」（回答的是"要不要新开一整席"，不是判据质量标准）：

1. **独立阅读方式**——读法与现有十一席均不同，不是从某个既有席位判据表拆出的子集；
2. **判据重叠 <20%**——实质判断对象与任一既有席位重叠须低于 20%，超过应并入既有席位；
3. **专属证据形态**——能产出其他席位给不出的证据形态或流程角色（如席01的来源侧引文、席08的两步制、席11的强制人工仲裁）；
4. **砍掉会漏一类错**——若把该席位从 `full` 预设去掉，是否存在一类真实缺陷从此没有任何现存席位能捕捉？答案为"不会，其他席位能兜底"则不满足准入。

四条全部满足才新增席位。另有独立的第二层检验——**新判据本身**（无论是加进已有席位还是新席位）还要再过一遍判据设计元规范（`docs/criteria-pool.md` 末尾）：RaR 四要件、HealthBench 三规则、Antislop 语境警告、消融警告。两层检验管的是两件不同的事（该不该开新席 / 单条判据写得好不好），互不替代。完整操作步骤见 `registry.md`「扩席说明」。

## 已知边界与风险（诚实区）

一个反 AI 味的工具，如果自己的 README 回避风险和边界，就说不过去。

**引文核验防捏造，不防"引真文说假话"**：阶段二的逐字核验只解决一个问题——这句话是不是真的出现在原文里。它防得住"编造一句原文里根本没有的引文"，防不住"引文确实存在，但 note 里对这句引文的断言/解读并不成立"。后者不是机械核验能力所及的问题，由互盲多席交叉核对与人工仲裁承接。使用报告的人应该知道这道防线止步于此——不要把"引文通过核验"读成"这条判定的论断一定站得住"。

**顺序路径互盲是尽力模拟，不是上下文隔离**：Claude Code 路径下，十一席是并行的 Task 子代理，上下文天然互相隔离，互盲是结构性保证。Codex 没有并行 subagent 机制，主会话依次扮演每一席，靠"显式声明丢弃上一席结论"来模拟人类评审员互不通气的效果——这是同一个对话上下文里的角色扮演，不是真正独立的进程或会话。语义上力求等价，但底层机制不同；对互盲严格性要求极高的场景，应该知道这个差异存在。

**判据公开是一把双刃剑（Goodhart 定律）**：全部判据文件随包公开分发，这既是本工具"可审计、可复核、可反驳"的基础，也意味着如果生成侧模型被专门训练或提示去"应付"这些具体判据句，理论上能在不真正提升文本质量的情况下让判据表看起来更漂亮——指标一旦被当成优化目标，就会失去指示价值。素读者（席08）与各席"自由观点"字段是天然的抗应试面：素读者读前完全看不到判据，自由观点不受判据束缚，两者都不是能靠"背题"绕过的固定考点。需要更强对抗性的场景，见上文"私有判据"。

**席11 不替代出版前场外授权**：席11 审的是文本内**呈现方式**是否有伦理风险（单方转述定性、隐私必要性、错误归因、弱者尊严），不替代针对真实人物的场外同意/授权检查。文本内呈现得体，不代表已经取得相关人物的发布同意——这一步仍需人工在文本之外单独完成。

**LLM 文学判断有天花板，评审团压缩的是方差，不是替代终审**：十一席互盲+机械核验+显式规则合成，能做到的是把"随手打个分"里的主观随意性和一次性偏差压下去，让判断变得可复核、可追问、可反驳。它做不到的是替代人类编辑或评论家的终审判断——分歧区特意保留"评审席之间也会互相不同意"这件事，不试图用更精巧的合成规则把分歧抹平成一个假装一致的结论。

### 验证边界（截至 v0.4.1）

以下机制**已有真机执行证据**（至少完整跑过一次评审并留有记录）：互盲分发（Claude Code 并行 Task 子代理路径、Codex 顺序模拟路径均跑过）；逐字核验+注毒作废（篡改一条引文后重跑核验，确认核验管道真的会拦下捏造引文，不是自我声明）；`quick`/`standard` 两档预设的报告组装；跨家族/异族评审（用不同模型家族执行评审，全流程零偏离）；**忠实链全链**（v0.2.1 规则终验：`--source` 目录逐文件核验、五态标签、CONTRADICTED 触发红线区与忠实带 C、矩阵产出"重写建议"——该轮忠实席抓出被评文本的支点性失实，来源侧引文 7/7 命中）；**veto 三层带位**（veto 判据中严重度命中→"最高 B + 人工复核"分支实测走通，对照旧规则下单条普通 core 判据即封 C 的误杀）；**NA 规则**（核心判据前提缺失时 NA 带理由，不再机械封带）；**双引文 note 承载契约**（89/89 核验零作废零格式违约，旧版「／」并置引文绝迹）；**失联处置协议**（十席全回传，对照旧轮一席永久失联）；素读者两步制与追加追问回收。

这份清单会随后续真机测试更新——在这些机制被验证前，请把它们当作"设计上自洽、尚未实证"，不要当作"已验证可靠"。

## 隐私

- 包内 `skills/lit-panel/references/anchors/`（A/B/C 三档参照样例）全部为**纯合成文本**，不含任何真实传主信息。
- 你提交评审的文本与素材（`--source`/`--brief`）只在你本地发起的 Claude Code / Codex 会话与其模型 API 之间流转，lit-panel 本身不引入除"运行评审所必需的模型调用"之外的任何网络传输、收集或外发路径。
- **建议生成与评审分会话**：不要在同一次对话里既让模型写稿、又让它评审自己刚写的稿——生成侧的自我评价不是评审真值，报告头部的"模型与会话披露"字段会如实记录这一点。可能的话，建议跨家族评审（如 Claude 生成 → Codex 评审，或反之），降低同一套潜在偏见既写又判的同源盲区。

## 方法溯源与致谢

判据不是凭空写的。每条判据都带溯源标签（【已核实】/【转译】/【二手待核】/【自研】），完整的逐条溯源清单见 `docs/criteria-pool.md`；这里只列这套判据体系借助最多的几个来源：

- **TTCW**（Torrance Test of Creative Writing）——叙事节奏、场景/概述平衡、结尾自然度、转折合理性、人物复杂度、情感灵活性、修辞复杂度等一整批 TW 系列判据的直接转译来源，主要分布在席04/05/06/07/09，另有 TW5（"故事的各元素共同构成统一、可理解、令人满足的整体"）并入席02（一致性审读），作为该席的整体连贯性收尾判据。
- **ConStory**——忠实审读与一致性审读的核心事实/一致性冲突分类法（命名混淆、数量冲突、时间冲突、同时性冲突、记忆冲突、地理冲突、社会规范违反等），两席判据的最大宗来源。
- **Measuring AI Slop**（配合 Antislop 词表法）——席03中文AI痕迹猎手的三主题十一维分类框架（密度/模板化/重复/语言不自然/冗长/用词失当/语气语域等），以及"词表命中不等于该处有错，判定必须过语境审"这条纪律的方法论来源。
- **EssayBench**——结构、人物、语言、情感多席里大量叙事写作技法判据的来源（选材、层次、人物塑造、环境描写、段落配置等）。
- **HANNA**——素读者席参与感与意外性高锚判据的来源。
- **HealthBench**——判据设计三规则（一条只查一个可观察行为、"例如"后的列举非穷举、风险判据判断的是坏现象是否出现）的方法论来源。
- **RaR**——判据设计四要件（专家指导依据、覆盖常见失败模式、core/extended/致命分层且禁数值权重、每条自足可独立回答）的方法论来源。

此外 AlignBench、EQ-bench、factool、lechmazur、高考作文评分标准等分散在各席个别判据里，完整清单以 `docs/criteria-pool.md` 为准。

**特别致谢**：席03 判据的证据词典 `slop-patterns-zh.md` 中，中文 AI 味模式的分类整理参考了 **shuorenhua**（MIT License，中文 AI 味检测开源项目）与 **speak-human-tw** 的公开分类思路——例句已按回忆录/口述史语域全部重新撰写，不逐字誊抄任一词表，也不与具体词条一一对应。
