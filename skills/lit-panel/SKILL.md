# lit-panel 编排逻辑

本文件是 `lit-panel` 三个分发平台（Claude Code plugin / Codex `~/.agents/skills/lit-panel/` / Google Antigravity `~/.gemini/config/skills/lit-panel/`）共用的**唯一权威编排流程**，也是**分发副本内的唯一执行权威**；本文件把 DESIGN 第 3–7 节转成 orchestrator 可逐步执行的操作说明，不引入新的产品决策。`docs/DESIGN.md` 是构建期规格（不随包分发——已安装到 `~/.claude/skills/` 或 `~/.agents/skills/` 的副本目录中不包含该文件）。若发现本文件与 `docs/DESIGN.md` 不一致，属构建缺陷——执行时以本文件为准，并请向项目仓库报告；不要在运行时查找或依赖 `docs/DESIGN.md`。

入口：`/lit-review`（单文评审）与 `/lit-compare`（A/B 对比）两条命令都会加载本文件并按其执行。本文件不重复席位表——席位数据源是 `references/registry.md`，本文件只描述"如何用这张表"。

## 0. 总览

```
参数解析 → 机械预检（阶段零，含致命失败网关）
  → 阶段一：并行评审（互盲分发，含素读者两步制）
  → 阶段二：机械核验（引证逐字核验，失败作废）
  → 阶段三：合成（执行 DESIGN §5 第 1–7 条显式规则，产出 references/report-template.md 结构的报告）
```
`--stability` 在阶段三之后追加一轮独立复跑并做判据级翻转率对比；`/lit-compare` 走独立的对比模式（见第 6 节），不复用阶段三的带位/决策矩阵。

## 1. 参数解析

| 参数 | 取值 | 说明 |
|---|---|---|
| `--preset` | `quick` \| `standard` \| `full` \| `custom(<席位号列表>)` | 决定本轮候选席位范围。**默认 `standard`**（未传 `--preset` 时按 standard 处理）。 |
| `--source <素材路径>` | 文件或目录路径 | 来源素材（访谈整理稿等）。决定席 01 是否激活。 |
| `--brief <编辑意图路径>` | 文件路径 | 编辑意图/任务书。决定席 10 是否激活，并触发机械预检的 brief 预处理。 |
| `--stability` | 开关（无值） | 触发第 7 节的稳定性自检：同配置静默跑两轮，报告判据级翻转率。 |
| `--readers=N` | 正整数，默认 `1` | 席 08（素读者）独立实例数。N 个读者互相互盲，各自完整走一遍两步制；报告的素读者报告区按读者编号分节列出。DESIGN.md 未显式定义该参数——这是本文件对"素读者"概念的原生扩展，用于降低单一读者主观波动；N>1 时的多读者聚合规则见第 5.3 节"素读者报警器"（v0.2.0 起该节同时承载报警器判定与多读者聚合两件事）。**与席位筛选无关**，不接受席位号或 agent name——筛选参评席位一律使用 `--preset custom(<列表>)`。（v0 约定：聚合规则见 §5.3，尚无上游规格背书，可能调整） |

**预设分档**（取自 `references/registry.md`，此处只重复取值，具体席位号以该文件为准）：
- `quick` = 01,02,03,08
- `standard` = 01–09 + 11（不含 10；提供 `--brief` 时 10 自动并入，见下方条件激活规则 2）
- `full` = 01–11
- `custom(<列表>)` = 用户显式枚举的席位号，例如 `--preset custom(01,03,08)`。列表中的编号必须是 `references/registry.md` 表中已注册的 `#` 值；出现未注册编号视为参数错误，在机械预检阶段直接报告并中止，不静默忽略、不静默丢弃该编号。

**条件激活席（覆盖预设范围的三条特殊规则）**：

1. **席 01（忠实审读）——"提供 `--source` 时"**：无论预设是否把 01 纳入候选范围，缺少 `--source` 时 01 一律跳过；报告"跳过席位及原因"记为"未提供 --source 素材"（若当前 `--preset` 为 `full`，前缀改为"警告：未提供 --source 素材"——full 的显式意图是启用全部十一席，缺输入未激活值得比其他预设更醒目地提示用户）。忠实带记 N/A。
2. **席 10（编辑意图审读）——"提供 `--brief` 时"**：是必要条件而非充分条件。只有当（a）预设范围满足"包含10"条件，且（b）提供了 `--brief`，10 才激活；二者缺一即跳过，原因分别记"预设范围不含席10"或"未提供 --brief"（若当前 `--preset` 为 `full` 且属于后一种情况，前缀改为"警告：未提供 --brief"，理由同席01）。**满足"包含10"条件的预设**：`full`、`standard`，或显式列出 10 的 `custom`。`standard` 的默认激活集合（01–09+11）数字区间本身不含 10，但只要提供 `--brief` 即自动并入，无需改用 `custom` 显式列出——这是 standard 预设的特别设计，让编辑意图审读随 brief 到场自动补齐。**`--brief` 存在不会把 `quick` 自动升级为包含 10**——`quick` 是唯一的例外，保持最小可用集，需改用 `standard`/`full` 或显式 `custom(...,10)` 才能激活 10。
3. **席 11（他者与伦理审读）——"回忆录默认开启"**：这是**充分覆盖**规则，与席 10 相反。只要被评文本判定为回忆录性质（体裁判断见第 2.5 节），无论 `--preset` 取值是 `quick`/`standard`/`full`，11 都自动追加进本轮激活集合——因为 11"不入带位"、成本极低而对真实第三方的伤害风险不可省略。例外：若用户显式使用 `custom(<列表>)` 且列表中不含 11，视为用户明确的范围选择，orchestrator 尊重该选择、不强行加回，但仍须在报告"跳过席位及原因"处追加一条警示："11（他者与伦理）被显式排除于 custom 席位列表，回忆录默认开启规则未生效"，不能悄悄略过这条提示。

其余席位（02–09）激活条件均为"总是"——只要在预设/自定义范围内即激活，无额外前置条件。

## 2. 机械预检（阶段零）

在打开任何席位之前，orchestrator 按顺序完成以下机械步骤。任一"致命失败"项命中即**不开席**，直接输出失败说明并停止，不生成 `references/report-template.md` 的其余任何区块。

### 2.1 文本完整性检测（致命失败网关）
检查被评文本是否截断或未完成：结尾出现明显未收束的半句、突兀的截断标记（如文件读取被长度上限打断）、成对符号（引号/括号/书名号）未闭合且无法用正常收尾解释、或文本长度与已知章节/篇幅预期明显不成比例。命中任一迹象 → **致命失败**：直接报告"文本在何处（给出最后一段可辨认的完整语句或字符位置）出现截断/未完成迹象，需提供完整文本后重试"，不进入阶段一。

### 2.2 输入登记
记录本轮是否提供 `--source`、是否提供 `--brief`，供第 1 节条件激活规则使用。

### 2.3 `--brief` 预处理（仅当提供 `--brief` 时）
独立预读 `--brief` 全文，提取并固化两项摘要：
- **核心戏剧目的**：这份 brief 希望本章/本文完成的主要叙事目标（一句话）。
- **关键戏剧任务**：为达成上述目的，brief 点名的具体人物/场景/事件/主题等必须呈现的要素清单。

这两项摘要是**orchestrator 在阶段一之前产出的既定材料**，随 `--brief` 原文一并发给席 10，供其判据 T2（"本章实现了 brief 的核心戏剧目的"）直接引用，而不是让席 10 自己重新从头摸索 brief 意图。

### 2.4 硬性约束机械核验（仅当提供 `--brief` 时）
从 `--brief` 原文中识别可编程判定的硬性约束——字数范围、指定开头/结尾字符串、结构组件是否存在、禁用内容关键词等——逐条独立核验：
- 字数范围：对被评文本做字符计数（中文按字数，不按 token）与 brief 声明的范围比较。
- 指定开头/结尾：对文本首尾做去空白后的字符串精确比对。
- 结构组件/禁用内容：做子串存在性/不存在性检查。

把每条约束的核验结果（满足/不满足 + 依据）作为既定事实随 `--brief` 一并发给席 10，避免席 10 用主观判断重复处理本可机械判定的项目。无法归类为机械可判定的约束（如"语气须庄重"）原样保留，交席 10 按判据完整评估。

### 2.5 体裁判断（回忆录识别，供第 1 节席 11 规则使用）
判断被评文本是否属于回忆录性质：依据 `--brief`/上下文中的体裁标注，或文本自身的第一人称真实经历叙述特征。lit-panel 的设计定位本就是"AI 生成的中文回忆录/叙事文本"（DESIGN §1），如无明确的反向体裁标注（如文本/brief 明确标注为纯虚构小说），默认按回忆录处理。

### 2.6 汇总激活席位清单
综合预设范围 + 第 1 节三条覆盖规则 + 本节体裁判断，得出本轮最终激活的席位号集合，连同每个被跳过席位的原因一并记录，供阶段一使用、最终写入报告头部。

### 2.7 元数据剥离
被评文本原始输入中若含 HTML 注释、frontmatter（如 YAML/Markdown 头部字段）等非正文元数据，orchestrator 在阶段一分发前将其从"被评文本全文"中剥离——分发给各席位（3.2 节标准分发包）的文本只保留正文内容，不含这类元数据。这类元数据**不作为评审正文看待，也不作为任何席位的引证来源**（quote 不得取自其中）。例外：第 2.5 节体裁判断可以参考这类元数据里的体裁标注（如存在）作为判断依据之一，但结论仍需体现为体裁判断步骤本身的输出，不代表元数据被当作可引证正文对待。剥离结果建议物化为一份独立的工作文本文件（各席分发与阶段二核验统一引用同一份），并存放在与历史评审报告不同的目录——避免顺序路径下他轮报告内容进入本轮上下文，也让核验脚本有稳定的比对基准。

## 3. 阶段一：并行评审（互盲分发）

### 3.1 取数据源
从 `references/registry.md` 按第 2.6 节汇总的席位号集合取出对应行（agent 文件 / agent name / 判据文件路径）。不在本文件内硬编码席位清单。

### 3.2 每席的标准分发包
每个激活席位收到且仅收到：
1. 被评文本全文。
2. 该席判据文件全文（`references/criteria/<对应文件>`）。
3. 下方 3.4 节的输出契约原文。
4. **仅席 03**：额外附带 `references/slop-patterns-zh.md`（中文 AI 味模式库）全文——03 的判据文件负责判据句本身，模式库负责"对照模式做 span 标记"的证据素材，两者都要发。**A7 判据（跨章复用检测）是否进入本轮判据集，由 `criteria/03-slop.md` 内自带的激活条件判定**（仅提供跨章语料时激活）；orchestrator 分发标准包时不做额外筛除或另行判断，03 席读到判据文件后按条件自行决定本轮是否作答该条。
5. **仅席 01**：额外附带 `--source` 全文（来源素材），用于来源侧引文核验。
6. **仅席 10**：额外附带 `--brief` 全文 + 第 2.3 节提取的核心戏剧目的/关键戏剧任务摘要 + 第 2.4 节硬性约束机械核验结果。

**席 08 例外（总则豁免，见 3.5 节）**：上面第 2、3 条（判据文件全文、3.4 节输出契约）**不适用于席 08 的第一步**——素读者第一步只收到第 1 条（被评文本全文），判据文件（`references/criteria/08-naive-reader.md`）与输出契约要求要到第二步才发送，且是单独一条消息，不与文本同批送达。这不是遗漏，是 3.5 节"读前不可见任何判据"纪律在分发包层面的强制落地；本节其余席位的"标准分发包"定义对席 08 不生效。

**互盲铁律**：分发包中不得出现任何其他席位的结论、判定倾向或"期望带位"。每个席位是完全独立的上下文。

### 3.3 三条执行路径

**Google Antigravity 路径（原生并行 Subagent 批量并发）**：
1. **批量并发派发**：对本轮激活的全部席位，orchestrator 调用 `invoke_subagent` 工具，在单个 tool call 中通过 `Subagents` 数组同批次并行发出各席位的派发请求。每个席位在物理隔离的独立上下文容器中运行，互盲天然成立。
2. **模型档位与权限配置**：
   - 评审席属结构化判据比对任务，各子代理统一指定 `Model: "flash"`（中档轻量推理模型，兼顾高速与低成本）；阶段三的复杂规则合成与报告组装由主 Agent 承担。
   - 子代理仅作审读诊断，不开启写文件或子代理派发权限，保持只读安全沙箱。
3. **素读者（席 08）两步制**：
   - 第一步：只发送被评文本正文，不附带判据与输出契约，等待素读者回传第一步自然语言体验报告；
   - 第二步：主 Agent 收到体验报告后，通过 `send_message` 工具向该素读者子代理发送 `08-naive-reader.md` 判据与追问题目（R 系列后测 + 三必答 + 传播意愿第四问），严格遵守读前无判据纪律。
4. **事件驱动等待（Reactive Wakeup）**：主 Agent 并发派发后无需轮询，利用平台的异步唤醒机制等待全部席位回传判定，再统一进入阶段二机械核验。

**Claude Code 路径（有并行 subagent 能力）**：对本轮激活的每个席位，使用 Task 工具派发 `agents/` 下对应的 subagent（`registry.md` 里的 agent name 一一对应），同批次并行发出全部席位的 Task 调用。互盲天然成立——各 subagent 上下文互相隔离。

**派发降级规则**：若按 `registry.md` 的 agent name 无法寻址对应 subagent（如本地目录副本未装为 plugin、或平台实际注册标识符与 registry 不一致），按以下顺序降级，不得因寻址失败直接跳过该席位：
1. 改用平台实际注册的标识符——**已实测确认**：装为 plugin 时，`claude plugin details <plugin>` 列出的 agent 组件名是**文件名**（如 `ethics-reviewer`），不是 agent 定义文件 frontmatter 里的 `name` 字段（如 registry.md 里登记的 `lit-ethics`）；若这个文件名标识符也不可达，再看平台当时的报错信息或 `Task` 工具可寻址的 subagent 列表，不假设进一步的固定格式。
2. 仍不可达则改用通用子代理（general-purpose），把 `agents/<file>.md` 正文整体作为 persona 注入派发。
3. 无论走第 1 步还是第 2 步，都必须在报告头部"模型与会话披露"字段注明本轮发生了寻址降级、降级到了哪一级，不得静默降级、不得让报告读者误以为全程按 registry 原生寻址执行。
4. 降级派发的模型档位：未显式指定时随平台会话默认；评审席属结构化判定任务，中档推理即可胜任、无需最高档，档位选择连同降级层级一并写入披露字段。

**Codex / 无并行路径（语义等价的顺序模拟）**：

1. **正文只在会话开头完整展示一次**：主会话开场先完整贴出被评文本全文（此时不附带任何席位的判据文件），作为本轮全部激活席位共享的阅读材料，后续不再重贴。这次开场展示天然就是一次"无判据的第一次阅读"——`references/slop-patterns-zh.md`「使用说明」里建议的"先无判据读一遍原文，留自然印象"（原为并行路径下的可选优化，此前顺序路径下需要专门豁免不适用）现在由这次开场展示本身满足，不需要再为 03 席单独豁免或另作安排。
2. 随后依次扮演每个激活席位，逐席开一个独立小节，标题形如 `### 执行席位 <#>：<agent name>`。小节内部严格按以下顺序呈现：
   1. 先贴一句**弃置声明**："以下评审不使用任何先前席位的结论，视文本为首读"——提醒模型本席判断不得携带任何前序席位已经说过的话，把开头已展示过的正文当作本席位的第一次接触，而不是"又读了一遍、且已经知道其他席位怎么判"。
   2. 再贴该席判据文件全文（+ 03/01/10 的额外材料，如适用）。
   3. 按 3.4 节输出契约作答——作答时引用开头已展示的正文，不重新粘贴正文本身。

**为什么正文只贴一次**：互盲纪律真正约束的是**席位结论**——不能让一席看到另一席已经下的判断、倾向或带位印象；它从未要求、也不需要"每席各自重新看一遍被评文本"这件事本身。正文内容对全部席位完全一致、不含任何席位专属信息，重复粘贴不产生任何额外的互盲保障，只产生重复消耗 token 与执行时间的成本——这是本轮性能优化里成本节省最大的一项。弃置声明承接的仍是互盲纪律本身（丢弃前序席位的结论），与"正文重贴与否"是两件独立的事，不因正文只贴一次而减弱。

**素读者两步制不受影响**：席 08 的两步制（见 3.5 节）第一步本来就只发送被评文本、不发送判据文件——与上面"正文只在开头展示一次、且不附带判据"的安排天然一致，不需要额外调整；第二步仍照常只追加判据文件与后测题，不重新提供文本。

### 3.4 输出契约（原样转录自 DESIGN §4，发给每个席位）

```markdown
## 席位判定：<agent name>
### 判据表
| id | verdict | quote | location | severity | note |
|----|---------|-------|----------|----------|------|
```

随输出契约一并说明以下规则（原样转录自 DESIGN §4/§7.4）：
- `verdict ∈ {YES, NO, ABSTAIN, NA}`。判据文件里每条判据自带极性（`[通过]`/`[风险]`）；对 `[风险]` 判据命中问题时答 YES。为避免混淆，席位作答时对 `[风险]` 判据在 `note` 开头写明"风险命中"或"风险未命中"。
- **quote 引证义务分级**：问题判定（`[通过]` NO / `[风险]` YES 命中）、veto 判据的任何判定（YES/NO 都要）、席 01 全部判定——这三类**必须**附逐字 quote，取自被评文本。**普通判据（非 veto、非问题判定）的通过判定**：`location` 仍必填，`quote` 可选，可留 `-`。ABSTAIN/NA 可留空 quote。
- **location 口径**：`location` 用"第N段"（按被评文本正文的自然段计数，不含标题、以及第 2.7 节已剥离的 HTML 注释/frontmatter 等非正文元数据）或行号，两种任选其一，但**同一份报告内必须全程保持单一口径**，不得各席各用一套、也不得同一报告内段号与行号混用。`quote` 是唯一的机械核验对象——阶段二核验只比对 `quote`（及 `note` 内固定标记引文）与原文的字符串包含关系，`location` 不参与机械核验，只是给人工读者定位用的辅助信息，location 记错不影响该条判定本身的核验结果。
- **双引文承载格式（冻结）**：`quote` 列在任何情况下只放**一条**正文逐字引文，禁止在 `quote` 列内用「／」分隔符或"（前）……（后）……"这类注记并置多条引文——这类并置写法机械核验时无法可靠拆解，一律视为格式违约。判定确实需要展示第二处引文（前后对照、呼应处、跨段互证等）时，第二条引文一律通过 `note` 字段末尾的固定标记承载：席 01 用 `来源引文：「...」`，席 02"确证矛盾"判定用 `对照引文：「...」`；其余席位若某条判定确需前后对照引文，统一沿用 `对照引文：「...」` 这一标记格式，不得自创其他标记或写法。阶段二机械核验范围=`quote` 列全部引文 + `note` 列内固定标记中的引文，两者各自独立核验，不需要、也不允许对 `quote` 列做拆分再核验——因为 `quote` 列本身已被这条规则限定为只含一条引文。
- **断言"全文不存在此类现象"的判定**（如 `[风险]` 判据未命中、无具体反例可指）：`quote` 列一律留 `-`，不得填入"（未出现符合条件的句子）"一类占位说明文字——占位说明文字不是逐字引文，核验管道会因"查无此文"把它当作捏造引文作废一条本来正确的判定；`-` 才是唯一合法的"无引文"表示。
- **问题判定**（`[通过]` 判据的 NO；`[风险]` 判据的 YES 命中）必附 severity（高/中/低）+ 修改建议；`[风险]` 判据未命中的 NO：severity 记 `-`、note 首写「风险未命中」，无需修改建议。
- **NA 必附理由**：NA 必附一句适用性理由（说明这条判据为何在本处不适用），无理由的 NA 按 ABSTAIN 处理；**仅 veto 判据的 NA** 列入报告人工仲裁区——普通 core/extended 判据的 NA（带理由）在分席判据表里正常可见，不升级到仲裁区。
- **席 01 专属约定**：每条判定的 `note` 字段**开头**固定标记该断言的五态标签（`SUPPORTED`/`PERMISSIBLE_INFERENCE`/`UNSUPPORTED`/`CONTRADICTED`/`UNVERIFIABLE` 之一，直接写英文态名，不翻译、不改写——与"风险命中"/"风险未命中"同样的固定标记法），`note` **末尾**追加固定标记 `来源引文：「...」`，填入来源侧的逐字引文（source quote）。五态标签不是新增表格列，来源引文也不是——DESIGN §4 的表格格式是"必须且只能"，因此这两项信息都通过 `note` 内的固定标记承载，供阶段二和阶段三红线区解析。
- **席 02 专属约定（仅用于"确证矛盾"类 NO 判定）**：`quote` 放冲突的第一处引文，`note` 末尾追加固定标记 `对照引文：「...」`（+ 该处 location，如与 `location` 列不同）承载冲突的第二处引文。同样是为满足阶段三红线区"附成对引文"的要求。
- **席 08 特殊**：第一步（体验报告）不用判据表格式，是纯自由文本；第二步（R 系列后测 + 三必答 + 传播意愿第四问）不套用本节"## 席位判定 + ### 判据表 + ### 自由观点"这一整套冻结的单次输出结构（没有"### 自由观点"，也不在第一步就给判据表），但 R 系列每条作答仍需给出 id/verdict/quote/location/severity/note 这组字段供 orchestrator 机械核验与报告组装，字段语义、双引文承载格式与本节规则相同；三必答是开放式问答，不走 verdict；**传播意愿第四问**（"你愿意把这篇讲给别人听吗？"）只接受"愿意"/"不愿意"二选一作答，同样不走 verdict、不受本节判据表规则约束，但答案格式严格受限（机判硬问题），是 5.3 节"素读者报警器"规则的直接输入。详见 3.5 节。

### 3.5 素读者两步制（席 08，含 `--readers=N` 展开）

对 `--readers=N` 指定的每一位读者（编号 1..N，默认 N=1），独立执行：

**第一步**：只发送被评文本全文，**不发送 `references/criteria/08-naive-reader.md` 的任何内容**。要求输出自由体验报告（自然语言，不受判据约束）。

**第二步**：收到第一步的体验报告后，再发送 `references/criteria/08-naive-reader.md` 中的 R 系列后测题 + 三必答（最亮处/最闷处/一句话转述）+ **传播意愿第四问**（"你愿意把这篇讲给别人听吗？"只接受"愿意"/"不愿意"）。不重新提供文本，只追问；R 系列每条作答需给出 id/verdict/quote/location/severity/note（字段语义与 3.4 节相同，quote 需逐字可核验，双引文承载格式规则同样适用），但不套用 3.4 节"## 席位判定 + ### 判据表 + ### 自由观点"的整套冻结结构；三必答是开放式问答，不走 verdict；传播意愿追问答案格式严格受限（只接受"愿意"/"不愿意"，不接受模糊作答），同样不走 verdict，但供 5.3 节"素读者报警器"规则直接使用。

若 N>1，各读者实例之间同样互盲：任一读者看不到其他读者的体验报告或后测答案；每位读者都独立走完整的两步制。

### 3.6 席位失联处置

无论并行路径（Task 子代理）还是 Codex 顺序路径，**任何情况下不得对单一席位无限等待**。按以下三步处置：

1. **判定失联**：单一席位（或素读者某一读者实例）超过合理等待时限仍未回传判定，视为"失联"。
2. **同席重派一次**：对失联席位，用完全相同的分发包（同一份判据文件、被评文本、输出契约，遵守 3.2 节的标准分发包定义）重新派发一次——不得更换判据内容或提示语，保持互盲铁律不变；同席重派不算污染，视为同一次评审的续跑。
3. **带缺口进入合成**：重派后仍未回传，该席不再等待，带着这个缺口直接进入阶段二/三；报告"跳过席位及原因"栏如实记录"执行失联，已重派一次仍未回传"，不得悄悄略过、不得伪造判定填补空缺。

orchestrator 在阶段一派发时应留存各席位的调用句柄/任务 ID，便于失联后定位重派对象或人工催收；每次失联与重派都应计入执行记录（如摩擦日志、worklog），供后续复盘判断失联是偶发还是系统性问题。

## 4. 阶段二：机械核验

对阶段一收集到的每一条含 `quote`（或 3.4 节所述 `note` 内固定标记引文）的判定，逐条核验其是否确实出自应在的原文。**核验范围=`quote` 列全部引文 + `note` 列内固定标记（`来源引文：「...」`/`对照引文：「...」`）中的引文**，两者各自独立核验。

**分层核验引擎（Tier 1–5）**：
阶段二机械核验采用 Tier 1–5 分层核验引擎（实现于 `scripts/verify-quotes.py`，供评审会话与独立复核复用）：
- **Tier 1: Exact（精确匹配）**：引文与目标原文做首尾空白 trim 后做精确子串包含匹配。
- **Tier 2: Normalized（归一化匹配）**：全角/半角、引号变体（“”‘’「」『』""''）、中文/英文标点、连续空白折叠及无标点压缩归一化匹配，消除模型格式化差异。
- **Tier 3: Span Ellipsis（省略号跨度匹配）**：智能识别引文中的省略号（`……`、`...`、`…`、`——`），拆分为有序片段依序在原文中查找跨度匹配，确保跨句引用真实存在。
- **Tier 4: Fuzzy Alignment（模糊对齐匹配）**：针对轻微字词笔误、错别字或 OCR 差异做字符级容错对齐与相似度计算（默认阈值 ≥ 0.85），防止伪造引文假阳性。
- **Tier 5: Void（作废与跳过）**：
  - 格式违约（如 `quote` 列出现「／」或"（前）……（后）……"等并置多引文）直接判作废；
  - 占位符（`"-"` 或空字符串）直接跳过，不计入通过/作废统计；
  - 目标素材缺失（如未提供 `--source` 却声明 `target="source"`、或缺少被评文本）判作废；
  - Tier 1–4 均未命中的捏造/查无此文引文判定作废并归入报告人工仲裁区。

**核验对象与目标文本的对应关系**：
- 普通席位（02–09、11）的 `quote` → 在**被评文本**原文中查找。
- 席 01 的 `quote` → 在被评文本中查找；`note` 内的"来源引文" → 在 `--source` 原文中查找。
- 席 02"确证矛盾"判定的 `note` 内"对照引文" → 同样在**被评文本**中查找（因为一致性矛盾是文本内部两处的冲突）。
- 席 10 的 `quote` → 在被评文本中查找。

**操作指引**（供 orchestrator 实际执行核验时使用）：
- 随包分发的机械核验工具：`python3 scripts/verify-quotes.py <quotes.json> <被评文本路径> [--source <来源素材路径或目录>] [--format text|markdown|json] [--fuzzy-threshold 0.85] [--max-tier 5]`。
- 本地文件场景：优先调用 `scripts/verify-quotes.py` 获得结构化 Tier 分级核验结果；快速命令行 grep 可用 `grep -F -- "<去空白后的引文>" <目标文本文件路径>`。
- **`--source` 为目录时**：来源引文核验逐文件尝试目录内各文件，**命中任一文件即算通过**，不要求命中同一个文件、也不要求遍历全部文件后才能判定失败（找到一处命中即可停止，仅当遍历完全部文件仍无命中才判失败）；通过时在 `note` 内固定标记后追加命中的具体文件名（如 `来源引文：「...」（命中：访谈稿2.md）`），便于人工复核定位来源出处。

**核验失败处理**：查无此文或格式违约的判定**作废**，移入报告"作废判定"区（人工仲裁区的子区），标注作废原因（如"Tier 5: 作废（quote 未在原文/来源中命中）"），同时完整保留原判定内容（verdict/quote/location/severity/note 原样附上），供人工复核判断。作废判定**不参与**阶段三的任何合成步骤——不进红线区、不进判据向量、不参与带位计算、不进分歧区——但必须完整列出，不能悄悄丢弃。

## 5. 阶段三：合成

Orchestrator 在本阶段**只执行下列显式规则，不引入任何未在规则中出现的二次审美判断**——阶段三的输入是阶段二核验通过的有效判定集合，输出是机械汇总/分组/矩阵查表的结果，不是 orchestrator 自己重新读一遍文本给出的主观印象。（5.3 节"锚点对照"是 DESIGN §5 规则 3 本身明确要求的步骤，不是这条纪律的例外，见该节说明。）

以下 1–7 条逐字对应 DESIGN §5 的合成规则；5.8（评分导出）为 v0.4.0 新增，DESIGN §5 同步新增对应条目；5.9（报告组装）即原第 7 条后的组装步骤，v0.4.0 起改用新报告结构：

### 5.1 红线区（DESIGN §5 规则 1）
筛选条件：席 01 中 verdict 为 CONTRADICTED，或 severity=高 的 UNSUPPORTED；加上席 02 中 severity=高 的"确证矛盾"NO 判定。汇总为红线清单，每条**附成对引文**：
- 席 01 来源：判定引文（被评文本内）+ `note` 中解析出的来源引文。
- 席 02 来源：`quote`（冲突第一处）+ `note` 中解析出的对照引文（冲突第二处）。

**红线不等于停止诊断**：红线区非空时，阶段三其余全部步骤（5.2–5.7）照常完整产出，不得因触发红线而提前终止报告。

### 5.2 判据向量（DESIGN §5 规则 2）
把全部有效（未作废）判定按席分组，原样列出 id/verdict/quote/location/severity/note。**禁止**做任何比例、计数转分数的运算——包括"通过率""命中率"这类衍生数字，哪怕只是展示性质，一律不生成。

### 5.3 带位规则（DESIGN §5 规则 3）

**极性解释前提**（判断"是否达标"前必须先做的一步）：每条判据在其判据文件里自带极性 `[通过]` 或 `[风险]`。"未达标"的真实含义是——`[通过]` 判据答 NO，或 `[风险]` 判据答 YES（命中问题）。orchestrator 判断带位前必须先查该 id 的极性，不能不看极性就把所有 NO 当负面、所有 YES 当正面。**术语约定（本节及下方 5.4/5.6/5.7 统一使用）**：**"问题判定"** = `[通过]` 判据的 NO，或 `[风险]` 判据命中问题的 YES（即上面的"未达标"）；**"通过判定"** = `[通过]` 判据的 YES，或 `[风险]` 判据未命中的 NO（即"达标"）。

**severity 的机械用途清单**（severity 不是描述性装饰，以下四处它直接改变机械结果，不是可有可无的附注）：
1. **忠实带阈值**：severity=高 的 UNSUPPORTED 才触发忠实带 C 封顶（见下方忠实带规则）；仅 severity=低 的问题只封顶到 B。
2. **红线区准入**（5.1 节）：severity=高 的席01 UNSUPPORTED、席02"确证矛盾"NO 才进红线区；同类型但 severity=中/低 的判定不进红线区，只进普通判据向量。
3. **veto 分档**（本节下方"文学带"规则）：同一条 veto 判据的问题判定，severity=高 封顶 C，severity=中/低 只到 B 并转人工仲裁——severity 直接决定走哪条分支，不是记录性质的旁注。
4. **修订包排序**（5.7 节）：修订包不允许换算成分数，但 severity（高/中/低）仍是修订会话优先处理顺序的依据。

**文学带**：判据取自席 04/05/06/07，这四席的 core 判据表内又分两层——**veto**（该席最致命的 ≤2 条核心判据，命中即代表该维度结构性坍塌；逐席清单见各席判据文件的"veto 判据表"，选择理由见 `criteria/CHANGELOG.md` v0.2.0 节）与**普通 core**（该席 core 表中除 veto 外的其余判据）。

**前置条件（必须先检查，再进入下面的分支判定）**：若本轮激活席位集合中**不含** 04/05/06/07 中的任何一席（典型情形：`quick` 预设且未用 `custom` 额外补选任一文学带核心席），文学带直接记 **N/A**（预设未覆盖文学带核心判据），**不进入下面 1–4 分支**——"四席 core 判据全部通过"这句话在没有任何一席实际开席时是空真（vacuously true，空集上的全称命题恒成立），不能被当作触发 A 候选的依据；报告结论区文学带处写"N/A（预设未覆盖）"。（`registry.md` 的 `quick` 预设说明与 `report-template.md` 头部编排说明已经这样描述，本条是把这个前提在算法规则层面显式钉死，避免只按下面 4 条字面执行时被空集情形绕过。）

满足前置条件（至少一席文学带核心席已激活）后，按以下优先级判定，自上而下第一条命中即停，不逐条都判一遍：
1. 存在 veto 判据的问题判定，且 severity=**高** → 文学带封顶 **C**。
2. 不满足 1，但存在 veto 判据的问题判定（severity=中/低）→ 文学带最高只到 **B**（不触发 C），且该条判定额外列入报告人工仲裁区供复核（见 5.5 节）——veto 判据的严重度判断本身直接左右带位结果，值得多一道人工核对这个判断是否准确。
3. 不满足 1、2，但四席"普通 core"判据中存在任一问题判定 → 文学带最高只到 **B**。
4. 四席全部 core 判据（veto + 普通 core）均为通过判定（零问题判定）→ 文学带候选 **A**——候选不等于确定：还需打开 `references/anchors/band-a.md`（必要时对照 `band-b.md`/`band-c.md`）通读，确认候选文本整体质感与锚点样例相当；明显不及则降级为 B，并在理由中注明"未达锚点样例质感，虽 core 判据全过"。**这一步锚点对照是 DESIGN §5 规则 3 明确要求的显式步骤，不是对"不做二次审美判断"原则的违反**——它本身就是被合成规则点名的机械动作之一，只是这个动作恰好是"读一遍锚点做定性比对"而非布尔运算。**素读者体验报告不参与这四条分支本身的判定**——第 4 条命中后，素读者改走下方"素读者报警器"规则单独核查，与 A/B/C 判定路径分离。

**惰性加载**：`references/anchors/` 三个文件（`band-a.md`/`band-b.md`/`band-c.md`）只在带位判定实际触达本条（第 4 条，四席 core 判据零问题判定）时才读取；判定落在上面第 1/2/3 条（文学带已封顶 C 或最高 B）时，不读取、不打开这三个文件——anchors 存在的唯一作用是 A 候选的质感校准，B/C 轮次用不上这一步，提前读入没有信息增量，只有 token 与时间成本。

**素读者报警器**（替代已废弃的 v0.1.1"素读者正向"参与 A 候选条件及其操作定义）：当上面第 4 条命中（四席 core 判据零问题判定，本应产出 A 候选）时，额外检查素读者对第四问"你愿意把这篇讲给别人听吗？"的回答（`criteria/08-naive-reader.md`，读后追问第四问，只接受"愿意"/"不愿意"）：
- **N=1**：答"愿意" → A 候选照常成立，按上面第 4 条继续走锚点对照。答"不愿意" → 触发报警：**不自动发 A，也不因此降级**，决策建议改写为"**A 候选（待人工确认——判据与读者感受分歧）**"，本轮该处**强制转人工仲裁**（见 5.5 节）——人工仲裁区注明触发原因，并指向"素读者报告"区对应小节，不必重复摘抄体验报告全文。
- **N>1**：以多数（过半数）读者的"愿意/不愿意"作答为准；平局按"不愿意"处理（宁可多触发一次人工核对，不静默放行）。
- **若席 08 本轮未激活**（如显式 `custom(...)` 排除了 08）：文学带 A 候选**一律转人工确认**——报警器结构上没有素读者输入可检查，不能默认视为"愿意"而放行 A，决策建议同样改写为"A 候选（待人工确认——素读者未激活，报警器无输入）"，强制转人工仲裁。
- 报警器只在"零 core NO"这个前提下才有意义——若判据面已经因 veto/core 问题判定封顶到 B 或 C，素读者答"不愿意"不再单独触发额外仲裁（问题已经由判据面捕捉，不重复报警）。

**忠实带**：完全基于席 01 五态分布（未开席 01 时记 **N/A**，不参与 5.6 决策矩阵的忠实维度判断，视为矩阵中的"其余组合"分支）。
- 存在 CONTRADICTED，或存在 severity=高 的 UNSUPPORTED → **C**。
- 不存在 CONTRADICTED、且不存在 severity=高 的 UNSUPPORTED，但存在 severity=中/低 的问题（或只有 PERMISSIBLE_INFERENCE/UNVERIFIABLE 而无 UNSUPPORTED/CONTRADICTED）→ **B**。
- 完全干净（无风险极性命中）→ **A**。

### 5.4 分歧区（DESIGN §5 规则 4）

**分歧操作定义**：满足以下任一条件即构成分歧——
1. 同一文本区域（location 相同/重叠/明显指向同一情节段落）上，"问题判定"与"通过判定"并存（定义见 5.3 节"术语约定"）；
2. 某席自由观点（或素读者体验报告/三必答）中，显式反对另一席判定可及的结论——即便这份反对意见没有走判据表 verdict，只要能明确指出反对的对象（id 或该判定所在文本区域），同样算分歧。

**扫描范围**：判据向量的全部有效判定（R 系列后测判定同样参与分歧扫描——席 08 虽不入判据向量，但 R 系列判定仍是有效判定；三必答/体验报告本身无 verdict，不参与第 1 类扫描，但参与第 2 类"自由观点显式异议"扫描）+ 各席自由观点/体验报告原文。orchestrator 必须显式检查各席自由观点是否包含针对他席判定的显式异议，不能只扫判据表就视为分歧扫描已完成。

逐组**并列呈现**双方内容——判据表来源的分歧用 id/verdict/quote/location/severity/note；自由观点来源的分歧引用该段原文 + 其反对的对方 id/verdict。**不平均、不加权、不裁决对错**，原样并列，留给人工/编辑判断。

### 5.5 人工仲裁区（DESIGN §5 规则 5）
收纳以下内容，分小节呈现、互不混合：
1. 全部 verdict=ABSTAIN 的有效判定（含 3.4 节"NA 必附理由"规则——无理由的 NA 降级而来的 ABSTAIN）。
2. 席 11（伦理）产出的**全部**判定，无论 verdict 为何——伦理发现不自动放行也不自动阻断（DESIGN §7.5）。
3. 阶段二作废的全部判定（附作废原因）。
4. **veto 判据的问题判定，且 severity=中/低**（5.3 节文学带规则第 2 条）——严重度判断本身直接影响带位，多一道人工核对。
5. **veto 判据的 NA**（附理由的 NA，见 3.4 节"NA 必附理由"规则——无理由的 NA 已归入上面第 1 类 ABSTAIN）——veto 判据对带位有直接封顶/仲裁后果，NA 意味着这层判断缺失，需要人工确认这个缺失是否合理。普通 core/extended 判据的 NA（带理由）不在此列，正常呈现在分席判据表，不升级到仲裁区。
6. **素读者报警器触发**（5.3 节"素读者报警器"）：四席 core 判据零问题判定，但素读者传播意愿判定为"不愿意"时，注明触发原因，并指向"素读者报告"区对应小节。

### 5.6 决策建议（DESIGN §5 规则 6）

**特例（矩阵退化：忠实带与文学带同为 N/A）**：若忠实带=N/A 且文学带=N/A（如 quick 预设且未提供 `--source`，忠实与文学核心判据均无输入可判），本轮没有任何带位输入可供矩阵查表——此时**不落入**下面"其余组合→修订后交付"分支，决策建议改为输出**"仅诊断（本预设与输入不足以定带）"**，并列出本轮全部"问题判定"（定义见 5.3 节"术语约定"）供人工参考，不得输出矩阵缺省值冒充真实决策。（此分支不是"重写"或"交付"类建议，不适用下方"建议最多 2 轮重写"终止提示，但仍须明确标注为诊断性输出而非裁决。）

**特例（素读者报警器触发）**：若 5.3 节"素读者报警器"触发，文学带此时是**待定状态**，不直接等同于 A、也不等同于 B。若矩阵此刻会因文学带=A 而与忠实带组合出"交付"（即忠实带同时=A）→ **拦截该结论**，决策建议改写为**"A 候选（待人工确认——判据与读者感受分歧）"**，本轮强制转人工仲裁（5.5 节），不适用下方"建议最多 2 轮重写"终止提示。若忠实带同时触发"重写建议"分支（忠实带=C）→ 忠实带优先，按矩阵正常输出"重写建议"，但仍须在人工仲裁区注明报警器已触发，不得因忠实带结论已定而略过这条记录。

其余情况按矩阵（忠实优先于文学）：
- 忠实带=A 且 文学带=A → **交付**。
- 忠实带=C 或 文学带=C → **重写建议**。
- 其余组合（含 B，或一侧为 N/A 而另一侧有 A/B/C 判定）→ **修订后交付**。

若席 10 被激活且其有效判定中出现"问题判定"（定义见 5.3 节）→ 无论矩阵结果如何（含上面的"仅诊断"特例），追加一条"修订项"（不改变主建议，只是追加编辑意图缺口的修订要求）。

正常（非"仅诊断"）分支下，输出必须明确标注为**建议**而非裁决，并包含终止提示原文：**建议最多 2 轮重写后转人工，避免无限自动重写循环**。

### 5.7 修订包（DESIGN §5 规则 7）
把红线区条目 + 判据向量中全部**"问题判定"**（`[通过]` 极性判据的 NO + `[风险]` 极性判据命中问题的 YES，定义见 5.3 节"术语约定"）汇总为可执行清单，每条含 id / quote / severity / 修改建议（取自该判定 note 字段）。允许与红线区有重叠——修订包是给下一轮修订会话的可执行清单，红线区是给人看的诊断，两者用途不同，不做去重。格式要求可直接喂给修订会话（表格或编号列表，字段名清楚、机器可解析）。

**重叠命中合并**：若多条判据命中**同一处文本片段**（quote 完全相同，或明显指向同一 span——席 03 的 A 系列判据常见），修订包为该片段只生成**一条**合并任务，不逐条重复：quote 取该片段引文（一次），id 栏列出全部命中的判据 id（如"A4, A5"），severity 取其中最高者，修改建议合并去重后呈现。**这是正式规格，不是留待调整的临时默认值**——同一片段的多条命中即便各自严重度不同，也只输出一条按"取最高值 + 合并建议"呈现的任务，不生成"同 quote、不同 severity"的多条并列任务。**合并只发生在修订包这一步**——判据向量（5.2 节）与阶段一各判据的独立判定不受影响，每条判据仍照常各自判定、各自计入判据向量，合并只是避免同一处文本在修订包里产生多条几乎相同的执行任务。

### 5.8 评分导出（v0.4.0 新增；视图层，不改变判据/带位规则本身）

本节从阶段一收集、阶段二核验通过的判据向量（5.2 节）按下列**确定性公式**机械导出 0-100 分数，供报告"多维评分表"与"总分卡"展示。**这是判据向量的一个数值化视图，不是新的判断**——公式只读取已有判定的 verdict/severity/极性，不引入本节之外的任何裁量；评审席契约（3.4 节输出契约）不因本节而改变一字，评审席本身不产生、也不需要意识到任何数字。作废判定（4 节）不计入任何分数导出的输入，如同它们不计入判据向量、带位计算一样。

**文学四维（0-100分，各自独立计算）**：结构=席04、人物=席05、语言=席06、情感=席07（v0.4.1 起原创=席09退出本均值，改走"原创加分"，见下文），四维各自只用该席自己的 core（含veto）+ extended 判据表计算，互不影响：
1. 基准 90。
2. 该席 veto 判据存在问题判定（定义见 5.3 节"术语约定"）：severity=**高** → 该维**封顶 ≤45**；severity=**中/低** → 该维**封顶 ≤65**。封顶与下面第3、4条的逐条扣分同时生效——先按扣分算出数值，再与封顶值取两者中**较小值**。
3. 该席**普通 core**判据（core 表中除 veto 外）每有一条问题判定，**−12**。
4. 该席 **extended** 判据每有一条问题判定，**−5**。
5. ABSTAIN/NA：不加不减，对分数零贡献。
6. 该席**零问题判定**（veto+core+extended 全部通过或 ABSTAIN/NA），且本轮阶段三**实际执行了** 5.3 节"锚点对照"步骤并确认候选文本质感与锚点样例相当：该维可从 90 上调至 **95-100**（幅度由定性比对结果决定，非自动满分）。**本轮未触发锚点对照**（文学带判定落在 5.3 节分支 1/2/3，未进入分支4）时，即便某一维度自身零问题判定，也维持基准 90，不擅自上调——锚点对照是上调的必要前提，不能绕过。

**等级映射**（本节全部0-100分制维度与总分共用；原创加分维不适用，见下文）：A=90+、A-=85-89、B+=80-84、B=70-79、C+=60-69、C=45-59、D<45。

**原创加分**（v0.4.1 新增；机械规则，仅加分，不扣分，不影响带位）：席09（原创性）v0.4.1 起不再计入文学基础分平均，退出veto/扣分/带位路径——其判定改为纯加分信号，照常评审（判定+引文+自由观点不变），问题判定降级为"可选打磨建议"（进问题与修订建议区与评委分论，不静音）：
- O 系通过类判据（O2/O3/O5/O6）**全部** YES 且**零** O 系问题判定 → 总分 **+5**。
- 通过类 ≥3 条 YES 且零问题判定 → 总分 **+3**。
- 其余情况（含任何 O 系问题判定，无论 severity）→ **+0**。**任何情况下不扣分**。
加分在席03修正与素读者报警旁标之后、忠实带总分封顶**之前**应用；加分后总分**上限 100**（超过100截断为100）；忠实带封顶（C→45、B→75）在加分之后仍然生效——先算出"文学四维均值+席03修正+原创加分"的中间值，再与忠实带封顶值取 min。

**AI 洁净度（0-100分，席03 导出）**：基准 100；A 系判据每有一条问题判定，**−3**（合计扣分上限 **−10**，即该维最低 90）。与下面"总分"里席03的扣分共享同一原始计数，不是两套独立权重。

**读者体验（0-100分，素读者 R 系列导出）**：基准 85；R 系列判据每有一条问题判定，**−10**。三必答与传播意愿不计入本项（无 verdict，不是判据表判定）。

**忠实度（0-100分，仅有 `--source` 时存在）**：直接取自 5.3 节"忠实带"已计算出的字母结论，按同一套封顶惯例数值化，不重新定义一套独立于忠实带的五态计数扣分规则：忠实带=**C** → **45**；忠实带=**B** → **65**；忠实带=**A** → 基准 **90**（此情形下按定义"完全干净、无风险极性命中"，通常无需再扣分）。无 `--source` 时本维度整体不存在——不出现在多维评分表，也不参与总分计算。

**总分（0-100分）** = 文学四维简单平均（不含 AI洁净度/读者体验/忠实度/原创加分——AI洁净度、读者体验、忠实度是补充展示维度不进均值，原创加分是均值算出后的加法修正），再按顺序叠加以下修正：
1. **席03 修正**：每条 A 系问题判定 **−3**，合计上限 **−10**。
2. **素读者报警旁标**：5.3 节"素读者报警器"本轮触发时，总分数字旁标注"⚠ 读者预警"，**不扣分**——这是可见性标记，不是分数修正。
3. **原创加分**（v0.4.1 新增，见上文"原创加分"）：+5／+3／+0，只加不减；加分后总分上限 100。
4. **忠实带总分封顶**（仅当本轮提供 `--source`；**最后应用**，即先算完上面两条修正的数值，再与本条封顶值取 min）：忠实带=**C** → 总分**封顶 45**，且决策建议**强制为"重写建议"**（忠实优先立场不变，覆盖 5.6 节矩阵原本推导的其他结论）；忠实带=**B** → 总分**封顶 75**。忠实带=A 或 N/A（未提供 source）时不封顶。

**总分等级**：与文学四维共用上方映射表。

**报告脚注（强制，逐字）**：报告分数区域必须原样附一行："分数由判据向量机械导出，评审席不产生任何数字。"

### 5.9 报告组装（v0.4.0 起结构调整；原 5.8 节内容迁移于此；v0.4.0 微调（6b）起区块标题去编号）

本轮阶段三产出物为**两份文件**：主报告（`references/report-template.md` 结构）+ 判据详表侧车（`<报告名>-details.md`）。按以下顺序把 5.1–5.8 的产出及 3.5 节的素读者报告填入主报告对应区块——**物理顺序即阅读顺序，区块标题不带编号**：

总评 → 红线警报（仅当有 source 且触发时出现）→ 总分卡 → 多维评分表 → 评委分论 → 问题与修订建议 → 需人工裁决（仅当有内容时出现）→ 评审档案 → 尾注。

**总评与评委分论的选材硬规则**：这两节的全部文字素材只能来自——各席自由观点原文的节选/微编辑、素读者体验报告原文的节选/微编辑、判定 note 字段的行文化改写。**禁止在合成层新增任何审美论断、任何席位未曾表达过的评价或判断**——orchestrator 在这两节做的是"编辑"（选择、裁剪、轻度改写以适配连续行文），不是"评审"；某个观察若在全部席位的自由观点/体验报告/note 中都找不到出处，就不能出现在总评或分论里，哪怕 orchestrator 自己读了文本后觉得这个观察是对的。这条规则与本文件开篇"阶段三只执行显式规则，不引入二次审美判断"的边界是同一件事在报告文风层面的落地，不是新增例外。

**总分卡**：来源=5.8 节评分导出。用二级标题+加粗呈现（如"## 总分：45/100 · C"），**不使用一级标题**——报告正文只有一个一级标题（报告本身的标题），区块标题一律不高于二级。

**多维评分表**：文学四维（结构/人物/语言/情感）+ AI洁净度（席03）+ 读者体验（素读者）+ 原创加分（席09，v0.4.1起呈现为**加分维**——本行显示 +5/+3/+0，不显示 0-100 分或等级，见 5.8 节"原创加分"）；有 `--source` 时追加忠实度（席01）。除原创加分维外，每维一行：维度名/分数/等级/一句话——一句话取该席自由观点中最凝练的一句（摘录+至多标点级微调，不新写）。

**评委分论**：每激活席一段，4-7句，真实评委口吻。素材=该席自由观点节选微编辑；问题判定的引文以行内引用织入行文（示例："她把菜下进锅里……"这样的开场看似寻常，却在源素材对照下露出了支点错位——张红芳本人反复说自己不会烧饭。／"婚姻像一盏灯"这样的收束固然妥帖，但在全篇至少复现三次的同类句式里，读起来更像习惯性反射而非当下的发现。）素读者一段用体验报告原文节选。**表格在本节禁止出现**——分论是评论文风的连续段落，不是判据表的另一种呈现。

**问题与修订建议**：原修订包（5.7 节）prose 化——每条＝位置＋行内引文＋为什么（取自 note）＋怎么改（取自 note 的修改建议），按 severity 排序（高→中→低），编号保留（沿用判据 id）供修订会话引用。

**需人工裁决**（v0.4.0 微调（6b）起本节全面禁止表格，与评委分论、问题与修订建议共享同一条"叙述文风"边界）：仅当 5.5 节人工仲裁区任一子类非空、或 5.4 节分歧区非空时出现，全部子类为空则整节不出现。每一类都写成**叙述条目**，不出现任何判据表：
- **ABSTAIN 判定**：叙述哪些席位/哪些判据 ABSTAIN，各自不确定原因一句话带过。
- **席11（他者与伦理）全部判定**：一段散文总结全部判定（含未命中项）——有命中说命中（引文+为什么归为发现）；全部未命中时以"[id列表]均未命中，其中[id]的[问题]需人工专项核实"这类收束句带过自由观点特别提示的场外语境缺口。
- **veto 判据待复核（中/低严重度）**：叙述哪条 veto 判据命中、severity=中/低、为什么这条严重度判断本身需要人核对。
- **veto 判据 NA 待复核**：叙述哪些 veto 判据被判 NA、适用性理由一句话。
- **素读者报警器触发**：触发时叙述触发的读者编号与原始答案。
- **分歧**：逐条叙述——谁与谁、各自立场一句话、行内「」引文、为什么需要人来裁，语气示例："原创席认为'婚姻像一盏灯'是情感散文高频收束公式（O1 命中·中），语言席却认为它以家常物象喻婚姻、贴合人物性情（TW3 通过）——同一句话两种读法，需编辑定夺。"自由观点类的隐性分歧（未走 verdict 但显式反对他席结论）同样写成叙述条目，不单独区分呈现方式。

每类叙述条目原始携带的 verdict/quote/location/severity/note 全字段表格移入判据详表侧车"人工裁决区详表"节，主报告本区末尾给一次性侧车指针，不逐条重复。

**评审档案**：原头部表格精简版——文本名、预设与激活席位（跳过席位并入本行一句话带过原因，不再逐条单列）、模型与降级披露、核验统计一行（通过N条/作废M条，逐条记录指针见详表侧车）、规则版本、详表侧车文件路径指针。不再单列"是否 stability 自检"字段。

**判据详表侧车**：文件名 `<报告名>-details.md`。结构=原"分席判据表汇总"+"阶段二核验统计"逐条记录 + **"人工裁决区详表"**（v0.4.0 微调（6b）新增，承载"需人工裁决"节全部叙述条目对应的原始表格——ABSTAIN/席11/veto复核/veto NA复核/分歧，各自保留原表格字段结构），原样保留表格格式（详表不受"分论/需人工裁决禁表格"约束）。修订会话若需逐条 id 对照原始 verdict/quote，指向侧车而非主报告。

**无 source 时的零忠实内容**（v0.4.0 起替代原"忠实核查缺席显性警示"整段规则）：未提供 `--source`（席01未激活）时——多维评分表**不出现**忠实度行（不留空行、不写 N/A）；总分卡**不出现**任何 N/A 字样；报告标题下**不再**强制输出旧版整行警示横幅；唯一的忠实性免责声明收缩为评审档案区**一行**："本轮未提供 --source，未做事实核查，评分仅反映文本内在质量。"这条规则只改变呈现位置与详略，不改变判断本身——忠实性确未核查这件事仍被诚实记录，只是从"标题下强制横幅"降级为"档案区一行事实陈述"，因为总分卡本身在无 source 时也会用小字注明"评分仅反映文本内在文学质量"，两处呼应，不需重复。

## 6. 对比模式（`/lit-compare`，A/B 两文本）

对比模式不复用阶段三的带位/决策矩阵,是独立流程：

1. **前提检查**：orchestrator 在预检阶段确认 A/B 同源同任务（同一被评对象的两个版本，或同一 brief 下的两个候选）。若明显不同源（不同任务、不同素材），提示用户确认后再继续，不静默对比。
2. **逐席双判**：对本轮激活的每个席位，做两次偏好判断——一次以 (A, B) 顺序呈现两文本，一次以 (B, A) 换序呈现。两次都要求给出偏好 + 理由（自由观点，格式仿照单文评审的"自由观点"字段）。
3. **一致性判定**：两次判断偏好同一文本（不论呈现顺序）→ 记录该席偏好=那一篇；两次判断随呈现顺序反转（换序后偏好也跟着换）→ 记 **TIE**。
4. **输出**：各席偏好 + 理由，以及全团偏好**分布**（如"7 席偏好 A、2 席偏好 B、2 席 TIE"这样的计数陈列）。**禁止把分布换算成总比分、百分比名次或加权结论**——分布只是陈列事实，不自动生成"A 获胜"这类判定。
5. **`--fast-compare`（性能旗标，默认关闭）**：默认行为（上面第 2 条）不变——每席对 A/B 做两次换序偏好判断。传入 `--fast-compare` 时，第 2 条改为**每席仅单评一次**（不换序）+ 一句席内自查声明（该席在自由观点末尾补一句，确认本次判断未受文本呈现顺序影响；这句声明是自我陈述，不构成机械防护）；第 3 条的 TIE 判定随之失效（单评没有第二次结果可比较，不产出 TIE），第 4 条的偏好分布照常输出。使用 `--fast-compare` 时，报告头部**强制**披露一行：「⚠️ 本轮对比使用 --fast-compare，未做换序双评，位置偏差（呈现顺序影响偏好判断）未受机械防护，仅有席内自查声明。」不得省略、不得改写措辞。`--fast-compare` 是用严谨度换速度的显式取舍：适合迭代轮，门禁轮（发布前终评）不建议使用。

## 7. 稳定性自检（`--stability`）

同一被评文本、同一 `--preset`、同一 `--readers` 设置，静默完整跑两轮（每轮各自独立执行第 2–5 节全部流程，两轮之间同样互盲——第二轮不得看到第一轮的任何产出）。

**报告内容**：判据级翻转率，按席分组展示——同一 id 在两轮中都产出有效判定、但 verdict 不一致（如一轮 YES 一轮 NO，或一轮 ABSTAIN 一轮有结论）的条目数 / 两轮都产出该 id 有效判定的条目总数。**不给单一总翻转率**，避免又制造一个总分幻觉。

稳定性报告是独立于两轮各自完整评审报告的附加产出，不反过来影响 5.6 决策建议——不能因为不稳定就自动判 C 或自动转人工，只是把不确定性摆出来给人看。

## 8. 纪律清单（逐条自查，原样转录自 DESIGN §7）

实现或执行本流程时逐条自查：

1. **互盲**：任何席位定义/提示中不得出现他席结论或"期望结论"；Codex 顺序路径下每换一席必须显式声明丢弃上一席结论（见 3.3 节）。
2. **评审席零打分；分数是导出视图**：判据向量、红线区、分歧区本身不得出现总分、加权分、百分比命中率等衍生数字（评审席契约不变，见 3.4 节）；报告的总分卡/多维评分表是 v0.4.0 起新增的例外——那里的分数由 5.8 节确定性公式对判据向量机械导出，是视图不是判断，全文公开、可复现，不是评审席自己报出的伪精确数字。
3. **引证逐字 + 核验 + 作废机制**：quote 必须逐字可查，阶段二核验失败一律作废，不静默放行、不启发式纠正。
4. **素读者读前不可见任何判据**：agent 定义里的后测题不得在读前展示——本文件在 3.5 节把发送拆成两步,严格保证顺序。
5. **ABSTAIN 转人工；席 11 发现一律人工仲裁**：不自动放行也不自动阻断（见 5.5 节）。
6. **分发包内不得含任何真实传主数据；anchors 必须纯合成**：`references/anchors/` 下的 band-a/b/c 样例是插件自带的校准材料，必须是纯合成文本，与运行时用户通过 `--source`/被评文本提供的真实素材无关——后者本就是本工具的正常处理对象，这条约束只管插件自带的参考材料。
7. **生成侧自评≠评审真值**：若生成方与评审方使用同一模型/同一会话，报告头部"模型与会话披露"须如实标注，并建议跨家族评审（如 Claude 生成 → Codex 评审）以降低自评偏差。
8. **中文-first**：所有判据、模板、报告使用中文；代码标识符（文件名、agent name、id、flag）保持英文/既定命名。
