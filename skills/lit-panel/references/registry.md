字段说明：
- **#**：两位数席位编号，`--preset custom(...)` 语法中引用的就是这一列。
- **agent 文件**：`agents/` 目录下该席位的 Claude Code subagent 定义文件名。
- **agent name**：subagent frontmatter 的 `name` 字段，Task 工具派发、Codex 顺序小节标题都用这个名字。
- **判据文件**：`skills/lit-panel/references/criteria/` 下该席位的判据文件相对路径。
- **方向一句话**：该席位读文本的角度，一句话定位（用于新席位准入判断时的"独立阅读方式"对照，见下文）。
- **激活条件**：`总是` 表示只要在预设/自定义范围内即激活；其余三种特殊条件见下节。
- **带位角色**：该席位判定是否、如何计入阶段三 5.3 节的带位规则。
- **特殊权限**：该席位在阶段三合成规则中的额外角色（红线权/仲裁权等）。

## 条件激活细则（三条特殊规则，供 SKILL.md 第 1 节引用）

| # | 规则类型 | 行为 |
|---|---|---|
| 01 | 必要条件，缺失即跳过 | 无 `--source` → 跳过，忠实带记 N/A |
| 10 | 必要条件（预设范围 + `--brief` 双闸），缺一即跳过 | 预设不含 10，或无 `--brief` → 跳过 |
| 11 | 默认开启，覆盖预设范围 | 回忆录性质文本 → 无论预设是否原生包含 11 都自动追加；仅当用户用 `custom(...)` 显式排除 11 时尊重该选择（但报告需警示） |

完整判定逻辑（体裁判断、`custom` 显式排除的警示措辞等）见 `skills/lit-panel/SKILL.md` 第 1 节，本表只是数据源，不重复完整规则文字以免和 SKILL.md 产生第二份可能漂移的副本。

## 预设分档定义

| 预设 | 席位集合 | 说明 |
|---|---|---|
| `quick` | 01, 02, 03, 08 | 最小可用集：来源忠实 + 内部一致 + AI 痕迹 + 素读者体验。不含任何"文学带核心席"（04/05/06/07/09），因此 quick 预设下文学带规则中的 core 判据集合为空——此时文学带不判定 A/B/C，只在报告中记"quick 预设未覆盖文学带核心判据，本轮不产出文学带"。 |
| `standard` | 01–09 + 11 | 默认预设。覆盖忠实（条件激活）、一致性、AI 痕迹、五席文学核心**全部**（04/05/06/07/09）、素读者、他者与伦理（回忆录默认开启），不含 10；若提供 `--brief`，10 自动并入本轮激活集合，不需要改用 `custom` 显式列出。 |
| `full` | 01–11 | 全席位。01/10 仍为条件激活席：缺少对应 `--source`/`--brief` 时，机械预检阶段以**警告**形式在"跳过席位及原因"中标注（如"警告：full 预设选择了席位01，但未提供 --source，该席位按条件跳过"），而非当作普通跳过静默处理——因为 full 的显式意图是启用全部十一席，缺输入未激活值得比 quick/standard 更醒目地提示用户；11 默认开启，在 full 下本就在范围内，因此"默认开启覆盖"对 full 没有额外效果。 |
| `custom(<列表>)` | 用户显式枚举 | 语法：`--preset custom(01,03,08)`，列表内为本表 `#` 列的两位数编号，逗号分隔。编号必须已在本表注册；未注册编号是参数错误，机械预检阶段直接报告并中止。 |

条件激活席在条件不满足时自动跳过，并在报告头部"跳过席位及原因"处注明（无论是因为预设范围不含该席，还是因为满足预设范围但缺少 `--source`/`--brief`）。

## 扩席说明：加一席 = 加一行 + 一个 agent 文件 + 一个判据文件

新增席位是"三件套"同步动作，缺一不可——注册表多一行但没有对应 agent/判据文件，会导致阶段一分发直接失败（读不到文件）。

### 准入规则（四条，新席位必须同时满足）

1. **独立阅读方式**：新席位必须有与现有 11 席均不同的"读法"——不是从某个既有席位的判据表里再拆出一个子集，而是整体上代表一种新的读文本角度（参照上表"方向一句话"列，11 席已分别代表忠实/一致性/AI痕迹/结构/人物/语言/情感/素读者体验/原创性/编辑意图/伦理这 11 种互不相同的读法）。
2. **判据重叠 <20%**：新席位判据条目的**实质判断对象**（不是措辞相似度）与任一既有席位判据重叠比例须低于 20%。超过则应并入既有席位的判据文件，而不是新开一席稀释互盲结构。
3. **专属证据形态**：新席位要能产出一种其他席位给不出的证据形态，类比：席 01 的"来源侧引文"（其他席位没有 source 可对照）、席 08 的"读后体验报告 + 后测两步制"（其他席位没有"读前无判据"的流程）、席 11 的"发现一律进入人工仲裁"（其他席位的发现按常规规则流入红线区/判据向量）。若新席位说不出任何专属证据形态或专属流程角色，它大概率只是某个既有席位的一个新判据条目，而不是一整个新席位。
4. **砍掉会漏一类错**：假设性检验——如果把该席位从 `full` 预设中去掉，是否存在一类真实会发生的缺陷，从此没有任何现存席位能捕捉到？如果答案是"不会，其他席位能兜底"，则不满足准入，不应新开席位。

四条全部满足才新增席位；只满足其中一部分（尤其是"听起来是个新角度"但重叠度其实很高）应优先考虑扩充既有席位的判据文件。

### 操作步骤

1. 在本文件"席位表"追加一行，分配下一个空闲的两位数 `#` 编号，按上表 8 列格式填写完整（不得留空列，"总是"以外的激活条件需和 SKILL.md 第 1 节的条件激活规则对齐，如需新增第四种条件类型，需同步更新 SKILL.md 第 1 节，不能只加表格行）。
2. 在 `agents/` 下新增 `<new-agent-file>.md`，遵循 `docs/DESIGN.md` §8 的 frontmatter 规范：`name`（=新行 agent name）、`description`（何时用+一句方向）、`tools: Read, Grep, Glob`（只读）；正文=席位 persona + 工作流（读判据文件→读文本→按 `skills/lit-panel/SKILL.md` 3.4 节输出契约作答）+ 纪律。
3. 在 `skills/lit-panel/references/criteria/` 下新增 `<NN>-<slug>.md`，遵循 `docs/DESIGN.md` §6 的判据文件规范（`id | 极性 | core/extended | 判据句 | 证据要求 | 溯源标签`，从 `docs/criteria-pool.md` 选取定稿或标注【自研】+理由），并在 `criteria/CHANGELOG.md` 记录本次判据取舍。
4. 若新席位需要出现在某个预设分档（`quick`/`standard`/`full`）而非只能通过 `custom` 触达，同步更新本文件"预设分档定义"一节。
5. 三步（表格行 / agent 文件 / 判据文件）必须在同一逻辑变更中一起落地；`criteria/CHANGELOG.md` 的记录和（如适用）预设分档更新一并完成，不允许只做部分步骤就视为扩席完成。
